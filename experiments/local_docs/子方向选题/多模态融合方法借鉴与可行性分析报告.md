**评估基准**：本课题「对齐条件下可见光—红外双光谱无人机检测」现有技术路线（YOLO26 四检测头 + 可变形跨模态融合颈 + mendeley 数据集 + RK3588 端侧）

|---|---|---|---|

## 1 Fusion-Mamba for Cross-modality Object Detection

### 1.1 论文定位与核心假设

arXiv:2404.09146（2024-04，北航 + 腾讯优图）。核心论点是：现有融合方法（CFT、ICAFusion、YOLO-MS）只做特征拼接或注意力交互，**忽视了模态视差（modality disparity）**——不同相机的焦距、安装位置、视角不同，导致两模态特征本就难以对齐，直接融合会把错位误差带进检测头。

作者的做法是把跨模态特征映射到一个**隐状态空间**中交互，用 Mamba 的线性复杂度替代 Transformer 的二次复杂度，从而在"降低模态差异"的同时降低算力。

**关键判断**：该假设的适用前提是「两模态存在几何/视角视差」。本课题主线数据集 mendeley 为**像素级对齐**，anti_uav300 的非对齐方向已被降为对照。因此 Fusion-Mamba 的主要收益来源在本文场景中**先天被削弱**，这一点必须写进评估，否则会误判其增益来源。

### 1.2 架构与关键模块

整体为 YOLOv8 双流骨干 + 三个 FMB（分别作用于 P3/P4/P5），neck 与 head 与 YOLOv8 保持一致。每个 FMB 由两部分组成：

| 模块 | 作用层级 | 机制 |
|---|---|---|
| **SSCS**（State Space Channel Swapping） | 浅层 | 在两模态特征间按通道切分并交换，制造显式的跨模态通道混合，再送入后续分支；本质是**无参数/极少参数的结构性交互** |
| **DSSF**（Dual State Space Fusion） | 深层 | 两路特征各自进入 VSS 块，在 SS2D 的隐状态中做关联与互补聚合，带门控；论文实现中堆叠 8 次 |
| **SS2D**（2D Selective Scan） | 基础算子 | 沿四个方向扫描成四条序列，各自过 S6 选择性扫描，再合并回 2D；线性复杂度 O(L) |

损失函数：沿用 YOLOv8 的检测损失，仅把坐标回归权重 λ_coord 调为 7.5（论文明确给出）。

### 1.3 实验与结论强度

在 M3FD 上相对 SOTA 提升 5.9% mAP，FLIR-Aligned 上提升 4.9%。注意 **FLIR-Aligned 是对齐数据集**——这说明即便在对齐条件下 Mamba 融合仍有增益，但其增益无法区分是"消除视差"还是"增强交互"，论文未做该消融。这是引用时必须指出的证据缺口。

### 1.4 代码与工程实现

- **未检索到官方开源仓库**。arXiv v1 正文与项目页均无代码链接；检索到的"完整 PyTorch 复现"来自第三方博客（AI 生成内容），不能作为工程基准。
- 复现依赖 `mamba_ssm` 的 `selective_scan_fn` / `causal_conv1d_fn`，属 **CUDA 专用算子**。
- 本仓库已内置 Mamba 模块族（[evssm.py](file:///c:/Users/不如喝茶去/Desktop/双光谱毕设/MutilModel_3485988898/ultralytics/nn/mamba/evssm.py)、[mamba_vss.py](file:///c:/Users/不如喝茶去/Desktop/双光谱毕设/MutilModel_3485988898/ultralytics/nn/mamba/mamba_vss.py)、[mamba_vision.py](file:///c:/Users/不如喝茶去/Desktop/双光谱毕设/MutilModel_3485988898/ultralytics/nn/mamba/mamba_vision.py)），但均为 `try: from mamba_ssm...` 导入，缺依赖时直接不可用。
- 更关键的是 [tasks.py](file:///c:/Users/不如喝茶去/Desktop/双光谱毕设/MutilModel_3485988898/ultralytics/nn/tasks.py#L1758) 已有注释：GPU-only 算子（mamba selective_scan_fn / causal_conv1d_fn）在**构建期 CPU stride 推断**时前向失败。这意味着模型**无法完成 CPU 侧图构建**，自然也无法走 ONNX 导出链路。

### 1.5 计算开销与部署约束

- 单个 DSSF 堆叠 8 次 × 4 个扫描方向，P3 分辨率下序列长度 L = H×W（640 输入、stride 8 时约 6400 token），显存与访存开销显著高于同层卷积融合。
- **RK3588 侧不可部署**：RKNN 工具链（2.3.2）不支持选择性扫描（SelectiveScan）类算子，且其 ONNX 导出本身在 CPU 构建阶段即失败。三条路（直接导出、算子替换、CPU 回退）均不成立。
- 结论：DSSF 只能作为**服务器侧对照实验**，用于回答"隐藏状态空间是否比可变形采样更优"这一学术问题，不能进入端侧链路。

### 1.6 可复用点

| 技术点 | 复用方式 | 理由 |
|---|---|---|
| SSCS 通道交换 | **可直接复用** | 仅依赖 split/cat/1×1 conv，ONNX 与 RKNN 均友好；本仓库 [partition_fusion.py](file:///c:/Users/不如喝茶去/Desktop/双光谱毕设/MutilModel_3485988898/ultralytics/nn/mm/partition_fusion.py) 的通道硬分割已具备同构能力 |
| "在共享空间交互以降低模态差异"的思想 | 概念可借 | 可作为创新点三「适用边界」的论证素材：对齐条件下该思想收益应收窄 |
| DSSF / SS2D | **不采纳** | 部署不可行，且前提假设在本文数据上不成立 |

## 2 TouchFormer: A Robust Transformer-based Framework for Multimodal Material Perception

### 2.1 论文定位

AAAI 2026（arXiv:2511.19509，中科院自动化所）。任务是**非视觉多模态材质分类**，输入为声音（S）、法向力（N）、摩擦力（F）、加速度（A）四路时序信号，输出材质类别。**注意：它不是检测任务，没有 bbox、没有密集预测。**

论文针对三个现实问题：模态噪声、模态缺失、模态重要性随任务动态变化。

### 2.2 三个核心模块

**(1) MAG（Modality-Adaptive Gating）**

```
H_m = ReLU(W1·X_m + b1)
g_m = σ(W2·H_m + b2)
若 g_m < gate_th，则该模态被判为"信息不足/噪声"，直接丢弃
α_m = softmax(g_m)              # 在保留模态间重归一化
Z_m = α_m ⊙ (X_m + PE)
```

设计意图：先**硬阈值剔除**低质量模态，再在剩余模态间做软加权。位置编码保证时序可分辨。

**(2) Intra-/Inter-modal Attention**

借鉴 MulT 的跨模态注意力，把源模态的低层特征注入目标模态，**不要求时序显式对齐**。这是它与"先对齐再融合"路线的根本区别，也是论文宣称能处理异步采样的依据。

**(3) CER（Cross-Instance Embedding Regularization）**

在嵌入空间做跨实例正则，拉开不同细粒度子类的原型间距，提升细粒度材质识别。

### 2.3 鲁棒性证据

论文的核心卖点是**模态损坏实验**：在 corruption ratio p 递增的条件下，基线模型（MTCNN、DDQN）大幅掉点，TouchFormer 掉点很小；模块消融显示该鲁棒性主要来自 MAG。这一实验设计比结果本身更有借鉴价值。

### 2.4 代码与依赖

- 项目页（touchformer.github.io）列出 Code 链接 `github.com/TouchFormer/Code`，但该仓库当前**不可公开访问**（返回 404 / 需登录），无法核查实现细节与依赖。
- 从论文方法描述推断，实现仅需标准 Transformer 组件（Linear、LayerNorm、MultiheadAttention），无特殊算子，**工程门槛低**。

### 2.5 可复用与不可复用

| 点 | 判定 | 说明 |
|---|---|---|
| MAG 的"两段式"门控结构（先 sigmoid 打分，再 softmax 归一化） | **需修改适配** | 思路可借，但**硬阈值不能照搬**：本文实测融合头对 IR 支路的置零响应仅 Δ=-0.006，IR 本就被旁路；若再加阈值丢弃，会直接把 IR 判为"低质量"剔除，加剧单边依赖 |
| 逐样本标量门控 | **不适用** | 无人机目标小、空间分布不均，整幅图一个标量权重粒度过粗；需改为**空间/通道级门控图** |
| 跨模态注意力免对齐 | **不适用** | 本文数据已像素级对齐，免对齐能力无收益，反而增加无序建模的自由度 |
| CER 跨实例正则 | **不适用** | 检测任务无"实例原型"概念，且单目标帧占比极高，跨实例对比样本不足 |
| **模态损坏鲁棒性评测协议** | **可直接复用** | 零训练成本，是创新点一最缺的证据类型 |

## 3 MPCNet: Multiscale Perception and Cross-Attention Feature Fusion Network for IRSTD

### 3.1 基本信息

IEEE TGRS, Vol. 64, Art. 5000915，2026-01-12 出版，DOI 10.1109/TGRS.2026.3653023。代码：`github.com/Wangtao-Bao/MPCNet`（已开源）。

### 3.2 任务与监督形式

**这是评估中最容易误判的一点**：MPCNet 做的是**红外小目标分割**（IRSTD），监督是 **mask**，评价指标是 IoU / Pd / Fa / F-measure，数据集为 NUAA-SIRST、IRSTD-1K、NUDT-SIRST。仓库目录结构为 `image/` + `mask/`。

因此：
- 没有 bbox 回归、没有置信度分支、没有 NMS/标签分配；
- 指标与 mAP 不可直接换算，**无法与本课题的四层基线做同表对比**；
- 它是**单模态**网络，"cross-attention"指编码器与解码器之间的**跨尺度**语义交互，**不是跨模态交互**。

### 3.3 三个模块

| 模块 | 位置 | 机制 |
|---|---|---|
| Multiscale Perception Module | 编码器 | 多尺度上下文聚合，增强小目标定位感知 |
| **GSFM**（Global Semantic-Aware Fusion） | 编码器 | 缩小不同层级特征之间的语义鸿沟，做更精细的层间融合 |
| **SCFM**（Semantic-Guided Cross-Attention Fusion） | 解码器 | 用编码器语义引导解码器特征，强化编解码之间的语义关联 |

### 3.4 工程实现与开销

- 代码高度借鉴 SCTransNet 与 DNANet（作者自述），整体为 U-Net 式编解码 + 多尺度注意力，依赖标准卷积与注意力，**无特殊算子**。
- 输入为小图块（IRSTD 常规 256×256），参数量与计算量远低于检测网络；GPU 单卡可训。
- 部署约束：干净（无自定义算子），但**其输出形态（mask）与本项目（bbox）不匹配**，不能作为端侧模块直接替换。

### 3.5 可复用点

| 点 | 判定 | 说明 |
|---|---|---|
| SCFM「深层语义引导浅层高分辨率特征」 | **需修改适配** | 可用于 neck 的 P3↔P5 之间，缓解小目标语义弱的问题；但需把全分辨率注意力改为**降采样 key/value + 单头**，否则 RK3588 延迟不可接受 |
| GSFM 缩小题间语义鸿沟 | 概念可借 | 与本项目已有的 PAN 结构部分重叠，边际收益需实测 |
| mask 监督 / IoU-Pd-Fa 指标 | **不适用** | 与 YOLO 检测范式不兼容 |
| 噪声鲁棒性实验（高斯/椒盐/散斑） | **可直接复用** | 补充"退化条件"维度，与 TouchFormer 的 corruption 实验互补 |

## 4 两项外部方案的借鉴意义

### 4.1 DPAFM：可学习门控注意力融合

**提案内容**：可见光与热红外特征自适应融合、模态退化抑制、候选区域召回。

**与现有实现的重叠度**：极高。项目内已有四个同族算子：

| 已有算子 | 机制 |
|---|---|
| [ReliabilityAwareFusion](file:///c:/Users/不如喝茶去/Desktop/双光谱毕设/MutilModel_3485988898/ultralytics/nn/mm/reliable_fusion.py#L20) | softmax 凸组合 `w0·rgb + w1·ir` |
| [GatedReliabilityFusion](file:///c:/Users/不如喝茶去/Desktop/双光谱毕设/MutilModel_3485988898/ultralytics/nn/mm/gated_fusion.py#L38) | 门控残差 `rgb + g·(ir−rgb)` |
| [DeformableCrossModalFusion](file:///c:/Users/不如喝茶去/Desktop/双光谱毕设/MutilModel_3485988898/ultralytics/nn/mm/deform_fusion.py#L75) | K 点可变形采样 + 内容注意力 + 门控残差 |
| [CGAFusion](file:///c:/Users/不如喝茶去/Desktop/双光谱毕设/MutilModel_3485988898/ultralytics/nn/modules/fusion/cgafusion.py#L79) | 空间 + 通道 + 像素三级注意力 |

**关键否定证据（项目内实测）**：融合头对 IR 支路**完全零响应**——把 IR 的 64 个通道全部置零，fuse 头 mAP 仅从 0.6914 变为 0.6858（Δ=-0.006，噪声量级）；梯度归因显示 fuse 损失 **75.6% 的梯度压在 RGB 支路**。

这正是 [partition_fusion.py](file:///c:/Users/不如喝茶去/Desktop/双光谱毕设/MutilModel_3485988898/ultralytics/nn/mm/partition_fusion.py#L1) 的设计动因：门控族算子的结构漏洞在于 **gate 有权整体趋 0**，前向旁路 IR、反向不给 IR 梯度。项目已做过三次训练期干预（约束 gate 取值）全部失败，最终结论是必须做**通道级硬分割**，让 IR 通路在结构上不可绕过。

**因此对 DPAFM 的判断**：
- "可学习门控注意力"本身**不能解决**模态退化/单边依赖，因为它仍属于"gate 可关闭"的拓扑；把它作为改进点会重复项目已经证伪的路线。
- "模态退化抑制"应重新定义为**评测协议**（在退化条件下测门控响应与掉点），而非一个新模块。
- "候选区域召回"与 YOLO 一阶段密集头不匹配；可改写为 `recall@k`（top-k 预测与 GT 匹配率），作为诊断指标而非模块目标。

**判定**：**不作为创新点；作为消融基线（Gated-Attn baseline）与诊断指标来源。**

### 4.2 HA-GNN：层次化注意力图神经网络

**提案内容**：候选目标建为图节点，解耦外观/空间注意力做关系推理，弱信号节点从邻近强节点借用语义。

**技术合理性**：在"密集小目标 + 单帧多实例"场景（如红外地面目标、人群检测）确实成立，且有成熟先例。

**在本文数据上的致命不匹配**：
- mendeley 共 5,834 帧，其中双目标帧仅 **41 帧（0.7%）**；绝大多数帧只有一个无人机。**图节点数为 1 时不存在"邻近强节点"**，关系推理退化为恒等映射。
- 测试集 614 帧同理，无法构造有意义的图结构，也无法做"弱节点借语义"的对照实验。
- YOLO26 端到端头虽有 top-k 查询（300 个），理论上可建查询图，但动态边索引、scatter/gather、稀疏消息传递在 RK3588 NPU 上**均无算子支持**，只能 CPU 回退，实时性不可接受。

**判定**：**不适用**。建议写入"未来工作"与"文献空白"讨论（多实例场景下的关系推理），不作为本课题实现内容。

## 6 可落地改进方案

### I1 门控不可关闭的可靠性约束（对应创新点一）

**做法**：在 `GatedReliabilityFusion` / `ChannelPartitionFusion` 的交互段末端，把门控权重的分布约束从"取值约束"改为"**结构约束 + 剖面约束**"：
- 结构侧：保持通道硬分割（IR 专属段无 gate），这是已被证明有效的唯一路径；
- 剖面侧：把「模态 × 场景」贡献剖面转化为门控初值或辅助损失（创新点一已有的第③步）。

**落点**：[gated_fusion.py](file:///c:/Users/不如喝茶去/Desktop/双光谱毕设/MutilModel_3485988898/ultralytics/nn/mm/gated_fusion.py#L73) 门控末端 + [partition_fusion.py](file:///c:/Users/不如喝茶去/Desktop/双光谱毕设/MutilModel_3485988898/ultralytics/nn/mm/partition_fusion.py#L64) 交互段

**预期收益**：mAP 提升有限（估 +0.005~0.02），但**验收指标应改为可解释量**——IR 置零敏感度从 Δ=-0.006 提升到 ≥0.02，即融合分支"确实在用 IR"。

**实现成本**：0.5 人日 + 2 组训练（有/无剖面约束）。

**风险**：过度约束可能压低绝对精度；须与 A0 基线同协议对比，不得跨协议比较。

**前置闸门**：M0（朴素拼接）必须跑完，否则无法区分"结构改动"与"算子复杂度"的贡献。

### I2 SSCS 式浅层通道交换（对应创新点一的结构子项）

**做法**：在 P3 级融合前，对两模态特征按比例切分通道并交换，再各接 1×1 conv 压回原维度。与现有 `ChannelPartitionFusion` 的区别是：后者在**输出端**硬分割，SSCS 在**输入端**交换，两者可叠加。

**预期收益**：估 +0.003~0.010 mAP；浅层小目标响应改善（可视化为热图前后对比）。

**实现成本**：< 50 行，0.5 人日 + 2 组训练；纯 split/cat/conv，**ONNX 与 RKNN 均友好**。

**风险**：与已有通道切分功能重叠，若单独增益 < 噪声带，应立即停止，避免"同义反复"式堆模块。

### I3 语义引导的跨层交叉注意力（对应小目标与创新点三）

**做法**：在 neck 内 P5→P3 的通路上加一个单头 cross-attention：P5 作 query（低分辨率），P3 作 key/value 但**先做 4× 降采样**，使 token 数 ≤ 1600；输出经 1×1 conv 与 P3 残差相加。

**预期收益**：总体 mAP 估 +0.010~0.020，小目标 AP_S 估 +0.02~0.04（需实测；本文目标在 640 输入下常 < 16 px）。

**实现成本**：1.5 人日，参数量 +0.2~0.4 M。

**风险与约束**：
- RK3588 上 attention 的 transpose 受 16K 限制，必须限制 token 数；
- 建议作为**训练版增益项**，并在附录 A 的部署方案中给出"部署版关闭该支路"的双版本策略，同时产出「增益—延迟」曲线，这正好可以作为创新点三「适用边界」的工程侧证据。

### I4 退化条件评测协议（证据链补强，零训练）

**做法**：在测试集上施加四类退化——高斯噪声（σ=10/20/30）、椒盐噪声（1%/3%/5%）、低照度（RGB 通道 γ 变换）、IR 对比度衰减；每一档独立评测 rgb 头、ir 头、fuse 头，产出「退化强度 × 分支」矩阵。

**预期收益**：不提升 mAP，但直接补上创新点一"贡献感知"最缺的证据：**在退化条件下门控是否按预期重新分配权重**（用 `last_gate_mean` 诊断量度量）。

**实现成本**：0.5 人日，零训练。

**风险**：退化合成方式需与真实传感器退化区分表述，避免被质疑"人造退化不代表真实域偏移"。

### I5 明确不做的四件事

1. 不用 FMB/DSSF 替换现有融合颈（不可部署 + 前提不成立）；
2. 不把 DPAFM 列为创新点（与已有门控族同构且已被证伪）；
3. 不实现 HA-GNN（数据不支撑）；
4. 不引入 MPCNet 的 mask 分支与 IoU 指标（范式不兼容）。

## 7 与三项创新点的归属关系

| 改进项 | 归属 | 说明 |
|---|---|---|
| I1 门控可靠性约束 | 创新点一（核心） | 属"贡献感知的融合权重调控"的实现细节，不另立创新点 |
| I2 SSCS 浅层交换 | 创新点一（结构子项） | 与非对称支路同属结构层，作为消融项而非独立贡献 |
| I3 语义引导跨层注意力 | 创新点三（判据的工程侧证据） | 产出「增益—延迟」曲线，支撑"何时值得融合"的判据 |
| I4 退化评测协议 | 创新点一 + 创新点二（证据） | 为"贡献随条件变化"与"域构成差异"提供同口径证据 |
| DPAFM / HA-GNN | 均不进入创新点 | 前者作基线，后者作未来工作 |

**边界提醒**：I1~I3 都是**对已有算子的改造或组合**，本身不构成新的学术命题。若把它们写成创新点，会与第四章已确立的三项创新点（度量—归因—判据）发生层级冲突。正确写法是：三项创新点给出"为什么这样改"，I1~I3 给出"具体怎么改"。

## 8 实施顺序与闸门

| 顺序 | 动作 | 前置条件 | 通过标准 | 不通过的处理 |
|---|---|---|---|---|
| 1 | I4 退化评测（零训练） | 四层基线权重就绪 | 能稳定复现「退化强度 × 分支」矩阵 | 检查退化合成是否改变了标注几何 |
| 2 | I1 门控可靠性约束 | M0 跑完，噪声带已标定 | IR 置零敏感度 ≥ 0.02 且总 mAP 不低于基线噪声带 | 回退到纯通道分割，I1 降为诊断结论 |
| 3 | I2 SSCS 浅层交换 | I1 结论稳定 | 单独增益 > 噪声带 | 判为同义反复，不写入论文 |
| 4 | I3 跨层注意力 + 双版本部署 | 服务器侧增益成立 | 总体 mAP 与 AP_S 均提升，且延迟增量可量化 | 仅保留训练版，作为适用边界讨论 |

**注意**：所有对比必须在同一口径（同一权重来源、同一 GT 源、同一积分方式）下完成。项目已发生过"跨口径比较导致结论反转"的教训，此处的闸门标准必须写入实验清单。

## 9 证据等级与待核实项

| 结论 | 证据等级 | 说明 |
|---|---|---|
| Fusion-Mamba 无官方代码、依赖 CUDA 专用算子 | 已核实 | arXiv v1 无代码链接；依赖项可从算法描述与生态通用实现确认 |
| TouchFormer 代码不可公开访问 | 已核实 | 项目页链接指向的仓库返回 404 |
| MPCNet 为 mask 监督的单模态分割 | 已核实 | 官方仓库目录结构 + 论文指标（IoU/Pd/Fa） |
| MPCNet 的 cross-attention 为跨尺度而非跨模态 | 已核实 | 摘要明确 GSFM/SCFM 均位于编码器内部与编解码之间 |
| 融合头对 IR 零响应、梯度 75.6% 压 RGB | 项目内实测 | 来自 `diag_channel_ablation.py` / `diag_fusion_grad_attribution.py` 的诊断记录 |
| 双目标帧 41 帧（0.7%） | 项目内实测 | 来自 mendeley 元数据统计 |
| 各项改进的 mAP 提升幅度 | **估算，待实测** | 文中已标注"估"，不得作为结论引用 |
| RKNN 对 GridSample/SelectiveScan 的支持情况 | **待板端实测** | 现有部署链路已依赖 `grid_sample`，须在转换阶段逐算子确认 |

**遗留风险**：现有 `ReliabilityAwareFusion` / `GatedReliabilityFusion` / `DeformableCrossModalFusion` 均调用 `F.grid_sample`，这本身已是端侧导出的高风险算子。附录 A 的部署方案应增加一条：**部署版用固定偏移的 3×3 可分离卷积近似可变形采样**，并与训练版做精度对齐验证。这一条比引入任何新论文模块都更紧迫。
