## 1. B1-1 改了什么

在原有三头（`rgb` / `ir` / `fuse`）基础上，为**融合分支**增设第二个检测头 `fuse_ir`：

- **输入特征**：与 `fuse` 头**完全相同**（复用同一组融合 neck 特征，层 47 / 49 / 51）
- **监督标签**：改用 **IR 坐标系**标签（`bboxes_ir` / `cls_ir`）
- **不改推理**：`fuse_ir` 只参与训练，`branch_order`（推理路径）仍为 `(rgb, ir, fuse)`

三条约束中，B1-1 只启用前两条：

| 约束 | 含义 | B1-1 是否启用 |
|---|---|---|
| **L1** | `fuse` 头 ↔ RGB 坐标系标签 | ✅ 原有 |
| **L2** | `fuse_ir` 头 ↔ IR 坐标系标签 | ✅ **本阶段新增** |
| **L3** | 两头预测一致性 | ❌ 留到 B1-2（`--mm-dual-w-fuse-ir-consist` 保持 0.0） |

`loss_items` 由 **9 项**（3 分支 × 3）扩为 **12 项**（4 分支 × 3）。

## 5. ⚠️ 必须先知道的两件事

### 5.1 本机无法执行训练

- GPU：`cuda_available=False`、`device_count=0`、无 `nvidia-smi`
- 数据：本地 `uav_data` 与 `uav_hard` 均**不存在**
- 结论：B1-1 的训练与评测**只能在 Kaggle / AutoDL 上跑**

### 5.2 B1 方案第六节的硬前提尚未满足（重要）

方案第六节明确指出：当前训练集**完全不含单模态可见帧**——`prepare_mm_dataset.py` 已把这类样本丢弃。原文：

> 「即使 B1 给了融合头『在 IR 坐标系下成立』的监督，它也**从未在『RGB 失效』的样本上被训练过**——因为训练集里根本没有这种样本。」

**这直接影响 B1-1 的效果预期**：L2 能让融合头在 IR 坐标系下多一条监督通路，但若训练集里不存在「RGB 失效」的样本，融合头很难学到「RGB 坏掉时靠 IR 兜底」的能力。方案给出了三项配套：

| 配套 | 内容 | 成本 |
|---|---|---|
| **S1** | 扩展数据生成，**保留**困难帧（不丢弃单模态可见样本） | 重新跑数据准备 |
| **S2** | Copy-paste / 模态 dropout 在线增广（`mm_modal_dropout_*` 已存在于 YAML） | 改配置即可 |
| **S3** | 训练时按模态可见性动态调权 | 改动最大 |

**建议**：先按现状跑一轮 B1-1 拿到基线数字；若 A 组 `fuse` 未达 0.1，再叠加 S1 + S2 重跑，把「数据前提」与「监督设计」两种因素的影响分开归因。方案第八节也建议跳过 A0-3 对照。

### 6.2 过程中修复的一个真实代码缺陷

**问题**：`ultralytics/nn/tasks.py` 的 `DetectionModel.init_criterion()` 里，B1 超参用
`float(getattr(args, key, default) or default)` 取值。由于 Python 中 `0.0` 是 falsy，
`0.0 or 1.0` 会返回 `1.0` —— **显式把某分支权重设为 0 会被静默改回 1.0**，权重开关实际上无效。

**影响面**：`mm_dual_w_rgb` / `mm_dual_w_ir` / `mm_dual_w_fuse` / `mm_dual_w_fuse_ir` 四项。
（`mm_dfs_weight` 等默认值本来就是 0.0 的项恰好不受影响。）

**修复**：引入 null-safe 取值辅助函数，只把「键不存在」当作缺省，不再把 `0.0` 当缺省：

```python
def _f(key, default):
    """从 args 取 float 超参，**不吞掉 0.0**。"""
    v = getattr(args, key, None)
    return default if v is None else float(v)
```

修复后复跑：冒烟 16/16 通过、B1-0 回归 **31/31 通过**（零退化）。

### 6.3 一条容易踩坑的调用路径（供调试参考）

`DetectionModel.__init__` 只收到 `cfg`(YAML) / `ch` / `nc`，**不含**训练超参，此时 `net.args`
是从 YAML 解析出的普通 `dict`（含 `mm_*` 默认值），且 `init_criterion` 用的是 `getattr`——
**用手写脚本直接 `net.init_criterion()` 是读不到 `mm_*` 覆盖值的**。

真实训练中生效的是 `DetectionTrainer.set_model_attributes()`：

```python
self.model.args = self.args      # self.args = get_cfg(cfg, overrides)，是 IterableSimpleNamespace
```

之后 `compute_loss → init_criterion` 的 `getattr` 才能读到 `train_full.py` 透传的值。
复现实验时应显式复刻这一步，否则会误判「权重没生效」。
