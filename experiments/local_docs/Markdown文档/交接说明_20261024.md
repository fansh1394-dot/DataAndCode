## 2. 已确立的结论（可直接引用）

### 2.1 标注几何（严格核验，3000 帧/split）

| split | 可判定帧 | 热斑质心落在 IR 框内 | 覆盖率 ≥0.9 | 覆盖率 ≤0.1 |
|---|---|---|---|---|
| train | 2993 | **89.07%** | 85.8% | 8.6% |
| val | 2984 | **90.35%** | 87.3% | 7.2% |
| test | 2961 | **77.27%** | 71.8% | 16.7% |

- `labels_ir` 与原始 `infrared.json` 逐位一致（中位误差 **0.00 / 0.00 px**）
- `images_ir` 与原始视频帧 phaseCorrelate 位移 **0.00 px**
- **IR 标签本身无问题，此问题已结案**

### 2.2 两套标注不共享坐标

- both 帧（11601）IoU 均值 **0.0432**，85.2% 帧 IoU < 0.10
- RGB 标签 vs IR 标签中心 dy 中位 **−38 px**，**27/27 序列同向**
- 反向对照：RGB 标签的热斑落在框内仅 **12%/15%**
- 物理成因：RGB 标机体，IR 标机体下方热源（相对位置随姿态变化）

### 2.3 融合在 test 上坍缩

| | test mAP50-95 |
|---|---|
| E1 纯 RGB-only | 0.568257 |
| C4 `fuse` | 0.558835（**−0.0094**）|
| `fusion_gain_over_rgb` | **+0.0016**（val 为 +0.0073）|

唯一稳定正增益：only_rgb 桶（75 帧）+0.0101。

### 2.4 `bboxes_ir` 绘图接线正确

YOLO26 的 `plot_training_samples` 传了 `batch["bboxes_ir"]`，A/B 对照证明：注入后框贴合热斑，不注入则整体上移 38px。

**YOLO11 的 `*_labels_ir.jpg` 看起来"没框住"是因为它没传 `bboxes_ir`，回退到 RGB 标签。不是数据问题。**

### 2.5 决策级路由（唯一正向融合结果）

| 方案 | 训练成本 | test 增益 |
|---|---|---|
| 特征级融合（E4 fuse） | 3×150 ep | −0.0095 |
| 决策级路由（tau 0.30/0.50） | **0** | **+0.00635** |

only_ir 召回 **0 → 98.19%**（652/664），路由准确率 94.99%，both 帧 FP 仅 +65。

⚠️ 该数字来自 `scripts/eval_late_fusion.py`（自写管线，always_rgb 比官方低 0.0295）。**进论文前必须在 `dual_val.py` 用官方评测器全量复跑**。接线已完成，冒烟通过，全量未跑。

## 4. 故障记录（本轮踩的坑，务必规避）

### 4.1 `ultralytics/models/` 整个目录丢失（最严重）

**现象**：链脚本连续 2 次失败，日志 `ModuleNotFoundError: No module named 'ultralytics.models'`，轮数=0。

**原因**：`ultralytics/models/` 目录被删除。其余 2871 个文件完好，只缺这一个目录（含 `yolo/multimodal/train.py`、`utils/multimodal/plotter.py` 等关键文件）。

**恢复**：`python scripts/_restore_models.py`（从本地打包 139 个 .py 上传）。

**验证**：`python scripts/_verify_import.py` → 输出 `import OK` + `DualHeadFusionDetectV26`。

**教训**：训练启动失败时先看完整 traceback 最后一行，不要只看"轮数=0"。

### 4.2 `_put.py` 参数顺序

正确：`python scripts/_put.py --dest scripts/ <文件>`
错误：`python scripts/_put.py <文件> --dest scripts/`（`--dest` 被当文件名）

### 4.3 PowerShell 引号地狱

远程命令里含 `$(...)`、单双引号嵌套时会报 `参数列表中缺少参数`。**所有多步逻辑必须落成服务器端 `.sh` 再 `bash <script>` 调用**。本轮已有：`_stop_v26_chain.sh`、`_status_v26.sh`、`_verify_import.py`。

### 4.4 链脚本不能覆盖运行中的源文件

bash 逐行读取，覆盖会导致读到错乱字节。**启动前先 `cp v26_chain2.sh .c2run.sh` 再执行快照**。

### 4.5 `pkill -f v26_chain2` 会自杀

命令行含该字符串。用 `/proc/*/cmdline` 逐个解析并排除 `MYPID`（见 `_stop_v26_chain.sh`）。

## 5. 待用户决策：论文立意重定向

### 5.1 新发现（本轮实测）

`v2c_R1_reg_early_s0` 已跑，但 **`mode: per-frame` + `oracle: True`**：

```
frame_err_median_px      = 0.0      ← 每帧用自身标签拟合，构造性完美
perseq_frame_ok_frac_2px = 0.1244   ← 逐序列固定仿射，达标率仅 12.4%（验收线 80%）
global_matrix            = [[0.794, 0.011, 58.75], [0.017, 1.139, -83.65]]
```

即便在最理想的 oracle 对齐下，`R1.1 (0.567959) − E1 (0.568984) = −0.0010`，**仍是负的**。

### 5.2 两种立意

**写法 A（原计划）**：非对齐导致融合失效，配准可修复
→ **数据反驳**：oracle 完美对齐都不涨

**写法 B（新，数据支持）**：两套标注的差异不止"非对齐"，还包含传感器成像机理不同（机体 vs 热源），这部分在几何上不可分离，因此任何基于几何对齐的融合方法都有理论上界
→ 支撑证据：`perseq_frame_ok_frac_2px = 12.4%`（仿射无法拟合）+ 热斑归属 89% vs 12% + oracle 对齐仍 −0.0010

**待用户确认走 A 还是 B。** 确认后才能写题目一提纲与新题目。
