## 〇、先明确两个概念（避免实验设计出错）

| 概念 | 含义 | 本项目取值 |
|---|---|---|
| **主干架构** | 网络骨架 | YOLO11n（框架仅提供 yolo11 系列的多模态配置） |
| **检测基线** | 论文里"我的方法优于它"的参照物 | `yolo11n-mm-mid`（标准中期融合，融合后为 C2PSA，无特色模块） |

**关键原则**：不能用自身已含改进模块的配置充当 baseline，否则构成"以改进版证明改进版"的循环论证，审稿人会直接质疑。

## 〇之二、2026-09-22 架构修订说明（**必读**）

### 修订动因：两模态视场不重合

对 Anti-UAV300 实测（34 对样本，val 前 2 序列）：

| 指标 | 数值 |
|---|---|
| RGB 与 IR 框中心归一化距离（中位） | **3.62 pp** |
| 同上（均值 / 最大） | 4.38 pp / **10.85 pp** |
| 距离 > 1 pp 的样本占比 | **100%** |

结论：RGB 与 IR 是**两个视场不同的相机**，同一目标在两幅图中的像素位置系统性偏移。
此前"把可见光标签映射到红外坐标系"的方案依赖人工肉眼配准，**误差过大已判定失败**。

### 由此产生的两个后果

**后果一：单头架构无法在红外图上出准框。**
用 RGB 标签监督唯一的检测头，它在 IR 坐标系下就是系统性偏移的（中位 3.62 pp）。

**后果二：融合分支没有独立监督。**
单头架构下融合通道的梯度只来自那一个头，没有任何损失项要求"融合结果优于单模态"，
融合可能退化为"等于较好的那个单模态"。

### 应对：新增「双头 + 融合分支」架构（第四种融合形态）

| 检测头 | 标签来源 | 坐标系 | 监督键 |
|---|---|---|---|
| `rgb` 头 | `labels/`（visible.json） | RGB | `batch["bboxes"]` |
| `ir` 头 | `labels_ir/`（infrared.json） | IR | `batch["bboxes_ir"]` |
| `fuse` 头 | `labels/`（visible.json） | RGB（融合主坐标系） | `batch["bboxes"]` |

**数据层配套**：`data.yaml` 新增 `labels: {rgb: labels, ir: labels_ir}` 双标签映射，
由 `scripts/prepare_mm_dataset.py --label-from dual`（默认）产出。

**关键设计**：几何变换（letterbox / mosaic / 仿射 / 翻转）两模态**共享同一矩阵与画布**，
但目标级过滤掩码（`box_candidates`、CutMix `indexes2`、CopyPaste `take`）**按模态独立计算**。

### 实测数据（用于论文"动机"一节）

RGB 与 IR 框中心归一化距离分布：中位 **3.62 pp**、均值 4.38 pp、最大 10.85 pp，
**100%** 样本 > 1 pp。这组数字直接量化了"单一标签无法同时服务两模态"的问题，
是双头架构必要性的核心证据。

## 一、核心发现：三个配置共享同一套骨架

经代码核查，以下三个配置的**双路骨干与 P4/P5 融合结构完全相同**，唯一差异是融合层之后插入的模块：

| 配置 | 融合后模块 | 定位 |
|---|---|---|
| `yolo11n-mm-mid` | `C2PSA` | **纯基线**（无特色模块） |
| `yolo11n-mm-mid-pki` | `Poly_Kernel_Inception_Block` | 改进版 A |
| `yolo11n-mm-c3k2_pkimodule` | `C3k2_PKIModule` | 改进版 B（项目原有） |

**这意味着消融实验的变量控制非常干净**——只换一个模块，其余全部不变。这是论文里最理想的消融设计。

## 二之二、A0 组：架构消融（新增，必做）

**目的**：证明「双头 + 融合分支」相对「单头融合」的必要性，回答两个问题：

1. **红外侧能否出准框？** —— 看 `ir` 头在其自身坐标系下的 mAP（这是单头架构做不到的）。
2. **融合头有独立监督后，是否强于单头融合？** —— 对比 `fuse` 头与 B 组单头配置。

| 编号 | 配置 | 检测头数 | 标签 | 说明 |
|---|---|---|---|---|
| A0-1 | `late-ref`（单头） | 1 | 仅 RGB 标签 | 单头对照：双 neck 拼接后单头检测 |
| A0-2 | `dual-fusion`（双头+融合） | 3 | RGB / IR / RGB 三路 | **本课题新架构** |
| A0-3 | `dual-fusion` 关 DFSC | 3 | 同上 | 消融 DFSC 语义一致性损失的贡献 |

**配置别名**（需在 `train_full.py` 中补入）：

| 别名 | 对应 YAML |
|---|---|
| `late-ref` | `cfg/models/mm/detect/yolo11/base/yolo11n-mm-late-ref.yaml` |
| **`dual-fusion`** | **`cfg/models/mm/detect/yolo11/base/yolo11n-mm-dual-fusion.yaml`** |

**命令示例**：

```bash
# A0-1 单头对照
python train_full.py --route A --config late-ref --name abl_A0-1_single_head

# A0-2 双头 + 融合分支（DFSC 开启）
python train_full.py --route A --config dual-fusion --mm-dfs-weight 0.5 \
    --name abl_A0-2_dual_head_dfs

# A0-3 双头（DFSC 关闭）
python train_full.py --route A --config dual-fusion --mm-dfs-weight 0.0 \
    --name abl_A0-3_dual_head_nodfs
```

**评测方式（关键差异）**：`dual-fusion` 走**分模态评测器**，一次推理产出三套 mAP：

```
metrics/rgb/metrics/mAP50-95(B)    ← rgb 头 vs RGB 标签
metrics/ir/metrics/mAP50-95(B)     ← ir  头 vs IR  标签
metrics/fuse/metrics/mAP50-95(B)   ← fuse 头 vs RGB 标签
metrics/fusion_gain_over_rgb       ← 融合相对 RGB 的增益
metrics/fusion_gain_over_ir        ← 融合相对 IR  的增益
```

**预期结论**：

| 断言 | 依据 |
|---|---|
| `fuse` > `rgb` 且 `fuse` > `ir` | `fusion_gain_*` 两个键均为正 |
| `ir` 头在 IR 标签下 mAP 显著高于单头模型在 IR 上的表现 | 单头模型无 IR 监督通路 |
| 开启 DFSC 后 `fuse` 进一步提升 | A0-2 vs A0-3 |

**论文呈现**：
1. 三路 mAP 分组柱状图（rgb / ir / fuse）；
2. **融合增益表**（`gain_over_rgb`、`gain_over_ir`），这是"融合优于单模态"的量化证据；
3. RGB 图与 IR 图的检测框可视化对照 —— 直观展示"红外图上框准了"。

> ⚠️ **重要**：报告 `ir` 头指标时**必须注明它使用 IR 坐标系标签**（来自 infrared.json），
> 与 `rgb`/`fuse` 头的 RGB 坐标系标签不同源。**三路 mAP 不可跨模态直接比较**，
> 只能各自与其对应的单模态基线比较。

## 三、A 组：模态消融（必做）

**目的**：证明"双光谱融合"本身带来增益，这是全课题的立足点。

| 编号 | 配置 | `single_modal` | 说明 |
|---|---|---|---|
| A1 | `baseline` | `rgb` | 仅可见光 |
| A2 | `baseline` | `x` | 仅红外（注意：参数值是 `x` 不是 `ir`） |
| A3 | `baseline` | （不设） | 双模态融合，即完整基线 |

**命令示例**：

```bash
python train_full.py --route A --config baseline --single-modal rgb --name abl_A1_rgb_only
python train_full.py --route A --config baseline --single-modal x   --name abl_A2_ir_only
python train_full.py --route A --config baseline                    --name abl_A3_dual
```

**预期结论**：A3 > A1 且 A3 > A2，尤其在弱光/夜间子集上差距更明显。

**论文呈现**：分组柱状图（mAP50 / mAP50-95），并按"白天/夜间"分层统计。**夜间分层是关键**——它直接体现双光谱的核心价值。

> ⚠️ **注意**：`single_modal` 的合法取值是 `['rgb', 'thermal', 'depth', 'x', 'fuse', None]`，红外对应 **`x`**。
> `trainMM.py` 原注释提醒："模态消融不等于单模态"，此处是**构建期的结构注入**，与 `modality` 参数（运行时消融）不同。

> ⚠️ **A2 标签来源修正（2026-09-22）**：A2 是"仅红外"单模态模型，其检测头只看红外图，
> 因此**必须用 `infrared.json` 派生的标签（`labels_ir/`）训练与评测**，而不是可见光标签。
> 若沿用可见光标签，A2 会继承 3.62 pp 的系统性偏移，导致"红外单模态"这一对照本身不可信。
>
> 实现方式：A2 的 `data.yaml` 设 `labels: {rgb: labels_ir, ir: labels_ir}`（主标签目录指向 `labels_ir`），
> 或直接以 `--label-from ir` 生成单标签数据集。
>
> **A1 同理**：A1 是"仅可见光"模型，用 `labels/`（visible.json）标签，保持默认即可。

## 四、B 组：融合策略消融（必做）

**目的**：论证"中期融合"是合理选择，同时展示你评估过其它方案。

| 编号 | 配置别名 | 融合方式 | 说明 |
|---|---|---|---|
| B1 | `early` | 早期融合 | 输入端拼接 |
| B2 | `baseline` | **中期融合** | 本项目采用（P4/P5 双层融合） |
| B3 | `late-ref` | 晚期融合 | 决策级参考（**单头**） |
| B4 | `asymmetric` | 非对称融合 | 主/辅模态不等权 |
| B5 | （自建） | 残差融合 | `yolo11n-mm-residual` |
| **B6** | **`dual-fusion`** | **双头 + 融合分支** | **新增：三头独立监督（详见 A0 组）** |

**命令示例**：

```bash
python train_full.py --route A --config early      --name abl_B1_early
python train_full.py --route A --config baseline   --name abl_B2_mid
python train_full.py --route A --config late-ref   --name abl_B3_late
python train_full.py --route A --config asymmetric --name abl_B4_asym
python train_full.py --route A --config dual-fusion --name abl_B6_dual
```

**预期结论**：中期融合兼顾浅层细节与深层语义，通常优于早期（噪声耦合）和晚期（信息损失）。
**B6 预期在融合头指标上最优**，但参数量也最高（n scale 下 6.14 M vs late-ref 5.14 M，+19.5%）。

**论文呈现**：表格 + 参数量/FLOPs 对比，说明中期融合在精度与算力间的平衡。
B6 单独列出时需说明其**额外开销换取的收益**（融合增益 + 红外侧可用性）。

> **B6 与 B3 的对照价值**：两者是"单头晚期融合"vs"三头晚期融合+融合分支"的直接对比，
> 在**完全相同的双 backbone + 双 neck 结构**下只改检测头数量与监督方式，
> 变量控制最干净。建议作为 B 组的核心对照。

## 四之二、B6 专项：DFSC 语义一致性消融（新增）

**目的**：单独量化 DFSC（目标级跨模态语义一致性损失）的贡献，与 A0-3 呼应。

**DFSC 是什么**：以**目标中心为锚点**采样 RGB / IR 两分支的语义特征，用余弦距离约束二者一致。

**为什么必须新增而非复用**：仓库既有的 `nn/mm/distill/losses.py` 中的"空间对齐"
（`F.interpolate`）解决的是**特征图尺寸不一致**，属几何层面；
DFSC 解决的是"同一目标在两模态下的**语义表示**是否一致"，属目标级内容层面。**两者不可互替。**

**为什么以目标为锚点**：两模态存在 3.62 pp 的视场偏移，逐像素对齐不可行；
以"同一个目标"为采样依据可天然免疫该偏移。

| 编号 | `mm_dfs_weight` | `mm_dfs_mode` | 说明 |
|---|---|---|---|
| B6-a | 0.0 | — | 关闭（= A0-3） |
| B6-b | 0.25 | `cls` | 弱约束 |
| B6-c | 0.5 | `cls` | 默认推荐 |
| B6-d | 1.0 | `cls` | 强约束 |

**命令示例**：

```bash
python train_full.py --route A --config dual-fusion --mm-dfs-weight 0.0  --name abl_B6a_dfs0
python train_full.py --route A --config dual-fusion --mm-dfs-weight 0.25 --name abl_B6b_dfs025
python train_full.py --route A --config dual-fusion --mm-dfs-weight 0.5  --name abl_B6c_dfs05
python train_full.py --route A --config dual-fusion --mm-dfs-weight 1.0  --name abl_B6d_dfs10
```

**相关超参**（`default.yaml`）：

```yaml
mm_dual_w_rgb: 1.0        # RGB 头检测损失权重
mm_dual_w_ir: 1.0         # IR  头检测损失权重
mm_dual_w_fuse: 1.0       # 融合头检测损失权重
mm_dfs_weight: 0.0        # DFSC 总权重（0=关闭）
mm_dfs_mode: cls          # 采样位置：'cls'=分类分支输出 | 'feat'=neck 特征图
mm_dfs_temperature: 1.0   # 余弦相似度温度
mm_dual_consist_weight: 0.0  # 跨头分类响应一致性（可选）
```

**训练期监控**：`DualHeadFusionCriterion` 暴露 `last_dfs` 与 `last_consist` 两个属性，
可在训练循环中记录，用于判断 DFSC 是否真正在起作用（值 > 0 且量级合理）。

> ⚠️ **踩坑记录（务必留意）**：跨头一致性（`mm_dual_consist_weight`）若在 **sigmoid 后的概率**
> 上计算 MSE，由于 Detect 头的 `cv3` 偏置初始化为负值（约 -4.6），初始概率仅 ~1e-3，
> MSE 只有 ~1e-8，**梯度近乎为零、正则项等于挂着不生效**（已实测确认）。
> 当前实现改为在 **logits** 上计算，量级恢复正常（~0.045）。若后续自行修改此项，请勿退回概率空间。

**论文呈现**：折线图（x = `mm_dfs_weight`，y = `fuse` 头 mAP），展示最优权重区间；
并附 `last_dfs` 曲线说明损失确实在收敛。

## 八、执行顺序建议

初期以拿到**可写论文的锚点数字**为目标，按此顺序：

| 阶段 | 内容 | 预计时长 |
|---|---|---|
| **第 0 步** | **数据准备：`prepare_mm_dataset.py --label-from dual` 生成双标签数据集** | **2-4 h** |
| **第 1 步** | **A0 组（架构消融）+ 冒烟测试** | **90-120 h** |
| 第 2 步 | C1（纯基线，路线 A） | 30-40 h |
| 第 3 步 | A1/A2（模态消融，A2 需 IR 标签） | 60-80 h |
| 第 4 步 | C2/C3（模块消融，可用 C1 权重初始化） | 50-60 h |
| 第 5 步 | B 组（融合策略，含 B6 与 DFSC 专项） | 120-170 h |
| 第 6 步 | D 组（小目标） | 30-40 h |
| 第 7 步 | E 组（对照方法与 RK3588 部署实测） | 视情况 |

**先跑 A0 的理由**：A0 是本轮架构修订的直接验证。若双头架构不能证明其价值，
则整个改造链条（数据层双标签 / 模型层多头 / 损失层多路 + DFSC / 评测层分模态）
都需要重新评估，后续实验设计也会连带调整。**先验证最不确定的假设。**

**A0 的内部顺序**：先跑 A0-1（单头 `late-ref`）建立对照锚点，
再跑 A0-2（双头 + DFSC），最后 A0-3（双头关 DFSC）。A0-2 与 A0-3 的差值即 DFSC 贡献。

**先跑 C1 的理由**：它是纯 YAML 构建、无可用预训练权重，只能随机初始化；
而其它实验都可从它出发加速。顺序反了会浪费算力。

## 十、需要先确认的事项

1. **单模态消融的参数值**：红外对应 `single_modal='x'`（非 `ir`），首次使用时建议先跑 `--epochs 2` 冒烟验证。
2. **`train_full.py` 是否支持 `--single-modal`**：当前脚本**尚未暴露该参数**，需补加。
3. **C2/C3 能否用 C1 权重初始化**：架构不同，参数名可能不完全匹配，需实测 `Transferred X/Y` 比例。
4. **RK3588 兼容性**：`Poly_Kernel_Inception_Block`、`C3k2_PKIModule` 等自定义算子能否被 RKNN-Toolkit2 转换，**需在选型阶段验证**，否则工程上不可部署。
5. **【新增】`train_full.py` 需补入 `dual-fusion` 别名**，并透传以下参数：
   `--mm-dfs-weight`、`--mm-dfs-mode`、`--mm-dual-w-rgb/ir/fuse`、`--mm-dual-consist-weight`。
6. **【新增】双头模型的评测自动切换**：`get_validator()` 已实现自动检测
   （`model[-1]` 为 `DualHeadFusionDetect` 时切到分模态评测器），**无需手动指定**，但需确认训练脚本未硬编码覆盖。
7. **【新增】双标签数据集必须先于所有实验生成**：`prepare_mm_dataset.py --label-from dual`
   （该已是默认值）。产出 `labels/` + `labels_ir/` + `data.yaml` 中的 `labels` 映射。
   若缺少 `labels` 映射，数据层会静默退回单标签模式（`dual_labels_configured=False`），
   IR 头将得不到监督 —— **这是最容易踩的坑，务必在训练日志中确认 `dual_labels_configured=True`**。
8. **【新增】RK3588 部署时多头的影响**：三头会带来额外计算量（+19.5% 参数），
   且 `DualHeadFusionDetect` 是自定义聚合层，需验证 RKNN 转换器是否支持 dict 型输出
   （可能需要在导出时改为只保留 `fuse` 头）。
