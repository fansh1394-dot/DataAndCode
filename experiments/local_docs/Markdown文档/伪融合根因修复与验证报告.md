## 二、伪融合根因修复（任务2）

### 2.1 根因回顾

历史因果探针（`diag_fusion_attribution.py`）三口径实测（S6a best.pt）已锁定根因：

| 口径 | fused 构造 | fuse mAP |
|------|-----------|:---:|
| 基准 orig | `rgb + g·(ir−rgb)` | **0.7123** |
| drop_rgb_term_scaled（幅值已归一） | `g·ir × 1.63` | **0.0054** |
| ir_only（纯 IR，全幅值） | `ir_warp` | **0.0066** |

补齐幅值后仍塌陷 → **排除幅值伪影**；给纯 IR 也解不出 → **融合头对 IR 半边几乎零解码能力**。
根因判定：**`fuse` 头恒定用 RGB 坐标系标签监督，优化目标里没有「必须用 IR」的压力**，于是它选了最省力的解——完全依赖 RGB 半边（伪融合）。

### 2.2 修复方案（B4-b：mask 条件下 fuse 头改用 IR 标签）

**核心思想**：把「融合颈 RGB 半边随机屏蔽」从一个单纯的扰动，升级为**显式的「必须用 IR」监督信号**。

- 训练时，被屏蔽（RGB 半边置零）的样本，其融合分支唯一可用信息源是 IR；
- 此时若仍用 RGB 标签监督，等于要求「无米之炊」，只会把 fuse 头压成常量背景（这正是 S7 蒸馏失败的深层原因）；
- **改用 IR 坐标系标签监督**，这些样本就变成了「必须从 IR 解码出目标框」的硬约束；
- 未屏蔽样本仍用 RGB 标签，保证主坐标系能力不退化。

与既有 B3 蒸馏的区别：B3 是对齐分类 logits（软约束，且 teacher `ir` 头可能弱于 student）；B4-b 是**直接用检测损失**施加硬监督，压力更强、更对症。

### 2.3 代码改动清单

| 文件 | 改动 |
|------|------|
| `ultralytics/nn/tasks.py` | 新增 `_mm_fusion_drop_per_sample`：逐样本屏蔽掩码（sample 口径直接用 `~keep`；batch 口径整批同值），并同步到检测头 |
| `ultralytics/nn/mm/dual_loss.py` | 新增 `_resolve_fuse_label_keys()`：按逐样本掩码合并 RGB/IR 两套标签（未屏蔽→RGB，屏蔽→IR），写入临时键供 `_prepare_targets` 读取；`_prepare_targets` 增加对 `__fuse_batch_idx__` 的支持；新增开关 `fuse_ir_label_on_mask` 与诊断量 `last_fuse_label_switched` |
| `ultralytics/cfg/default.yaml` | 新增 `mm_fuse_ir_label_on_mask: true` |
| `train_full.py` | 新增 `--mm-fuse-ir-label-on-mask {true,false}` CLI 参数并透传 |

**向后兼容保证**：掩码为 `None` 或全 False 时，`_resolve_fuse_label_keys` 直接返回原始键（零开销），与改造前**逐位一致**。
