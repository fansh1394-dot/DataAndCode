## 2. 对「鸟机混淆：外观—运动双证据三态判别」的可借鉴性

**能借的（外观证据侧）**
1. **差分作为跨模态交互信号**：`diff = suppl - x` 直接作为交叉注意力的 K/V。这与我们现有 `GatedReliabilityFusion`（`base + g·(ir - rgb)`）在思想上同源，可作为我们融合模块的方法学对照与引用；若后续要增强"IR 被训练关闭"的问题，这是可引证的做法之一。
2. **双向交叉注意力 + 求和**（`FusionModule`）：可作为"融合不该是单向投影"的论据。

**不能借的（运动证据侧）——这条必须写死**
- 代码中**没有任何显式运动表征**：无光流（`flow_warp` 仅 import 未用）、无帧差、无轨迹、无速度/方向量。`CoAttentionModule` 提供的是**隐式时序平滑/上下文聚合**，输出的是一张特征图，不产生可解释的运动量。
- 而"鸟机三态判别"需要的运动证据是：帧间位移方向与大小、尺度变化率、扑翼周期性（外观随时间的振荡）、刚体匀速性。这些**都无法**从共注意力输出中读出。
- 因此：**VideoFusion 只能证明"双模态视频的时序建模可行且能抑制闪烁"，不能作为鸟机判别的方法来源**。引言/相关工作里只能作为旁证引用，不能写成"借鉴其运动线索"。若越界引用，答辩时一问"你的运动量从哪个张量取"就无法回答。

**可借用但需改造的形式**
- 取其"前后各一帧"的窗口结构（`t-1, t, t+1`），但运动证据必须改为可解释量（帧间框中心位移、尺度比、外观序列的周期性度量），且这些量应显式进入判别器，而不是只靠注意力隐式吸收。

## 3. 时序一致性度量：核验结果

- **仓库没有独立的一致性度量实现**。`basicsr/metrics/` 下只有 `fid.py`、`niqe.py`、`psnr_ssim.py`、`metric_util.py`；全仓未检索到 `temporal` / `consistency` / `DST` 相关文件。
- 根目录 `test.py` 是 BasisSR 通用推理入口，只调用 `model.validation(...)`，不含时序分析逻辑。
- README 中的 "temporal variation of metrics on sequences" 与 "沿列像素亮度变化" 属于**分析/可视化协议**（图注写明 "Following DSTNet"），不是可复用的打包指标。

**因此：不能声称"采用 VideoFusion 的时序一致性指标"，只能声称"同构移植其度量思想"** —— 序列内波动 + 沿空间切片的逐帧变化。下面的指标全部由我们自己定义并实现。

## 4. 检测侧同构指标定义（可直接实现）

### 4.0 数据基础与口径

| 项 | 值 |
|---|---|
| 测试集 | 614 帧 / 51 序列 / 552 GT |
| 已有产物 | `perframe_boxes2/boxes_<tag>.json`（逐帧四头框）、`ratio_<tag>.json`（每帧缩放/填充） |
| GT 形式 | 每帧 YOLO txt，**无 track id** |
| 依赖 | 不重新训练、不改推理、不涉及 RK3588 部署 |

标注坐标统一反算到原图像素：`x = (x_l - pad_x)/gain_x`，与 `bucket_ap.py` 现有逻辑一致。

### 4.1 前置：轨迹构造（不定义这一步，抖动指标无意义）

1. 帧排序：按 `<序列名>/<帧号>` 字典序；序列名取自 GT 路径的父目录。
2. 相邻帧关联：对 `(t, t+1)` 的 GT 框做一对一贪心匹配，代价 `1 - IoU`，接受阈值 `IoU > 0.3`；未匹配则断开、新建轨迹。
3. 只统计长度 `T >= 3` 的轨迹；报告 `N_track`、长度分布。
4. **敏感性分析必做**：阈值取 `0.2 / 0.3 / 0.5` 各算一遍，若三档结论同向才可写进论文（GT 无 ID，关联误差会直接污染抖动指标）。

### 4.2 指标一：框 IoU 抖动（Box Jitter, BJ）

对每条轨迹相邻帧对 `(t, t+1)`：

```
P_t   = 与 GT_t 匹配（IoU>=0.5）的最高分预测框
P_t1  = 与 GT_{t+1} 匹配的最高分预测框
BJ(t) = 1 - IoU(P_t, P_t1)          ∈ [0, 1]，越小越稳
```

- 若任一帧未匹配成功，该帧对**不计入 BJ**（缺失记入 4.3 的闪烁率），并单独报告"轨迹覆盖率"。
- 聚合：中位数 `BJ_med` + 90 分位 `BJ_P90`（均值会被离群主导，不作为主指标）。
- **必须分桶**：`lt16 / 16-32 / 32-64 / >64 px`。IoU 与尺度无关，但 1 px 位移对 8 px 框的影响远大于 64 px 框，总体值会掩盖极小目标的问题。
- 对应 VideoFusion 的"沿列像素亮度变化"：都是"沿时间轴衡量同一空间对应物的变化量"，只是我们把像素亮度换成框几何。

### 4.3 指标二：置信度闪烁率（Confidence Flicker Rate, CFR）

对每条轨迹的每个 GT：

```
h_t = 1[ 存在与 GT_t 的 IoU>=0.5 且 conf>=τ 的预测 ]
CFR_track = Σ_t |h_t - h_{t+1}| / (T - 1)
```

- 主口径 `τ = 0.25`（与 `R@0.25` 对齐）；附加 `τ ∈ {0.1, 0.5}` 敏感性。
- 辅助量：置信度漂移 `median_t |c_{t+1} - c_t| / max(c_t, c_{t+1})`，只在两帧都命中时计算。
- 聚合：轨迹级 CFR 的均值 + 命中率 `mean(h_t)`；分桶报告。
- 解释口径：CFR 高 = 目标"忽隐忽现"，这是端侧监测系统最直接的失效模式。它与召回率相关但**不冗余**：召回只看单帧，CFR 看帧间连续性。

### 4.4 指标三：序列级 AP 方差（Seq-AP Var）

对每个序列 `s` 单独计算 AP50-95（沿用 `bucket_ap.py` 的 101 点插值实现），得到 `{AP_s}`：

```
报告：mean(AP_s)、σ_seq = std(AP_s)、worst-10% = 最低 10% 序列的 AP 均值
同时给出 lt16 桶的 σ_seq
```

- **统计门槛**：只对 `GT_s >= 5` 的序列计算（本项目均值约 11 GT/序列，单序列 AP 天生抖动大）；报告每个序列的 GT 数。
- 解读：总体 AP 高而 `σ_seq` 大 = "在少数场景整体失效"，对监测系统比均值更值得报告；这与 VideoFusion 的"指标随序列波动"同构。
- 不作为主表的替代指标，只作为稳定性补充列。

### 4.5 汇总表（已跑出基线，每 tag 一行）

| tag | BJcomp_med(lt16) | BJcomp_P90(lt16) | CFR@0.25(lt16) | σ_seq(AP50-95) | worst-10% | 轨迹覆盖率 |
|---|---|---|---|---|---|---|
| `s0`（基线） | 0.232 | 0.401 | 0.177 | 0.123 | 0.504 | 0.961 |
| `s1`（种子1） | 0.222 | 0.362 | 0.177 | 0.106 | 0.524 | 0.955 |

| VideoFusion（融合视频） | 本项目（检测） |

| 时序一致性视觉对比中的"闪烁" | 置信度闪烁率 CFR |

### 4.6 实测口径修正（2026-11-05，必须写进论文的实验设置）

首次跑通后发现两处与 §4.1/§4.2 的原始假设不符，已按下列方式修正并写入脚本：

1. **关联不能用纯 IoU 阈值**：测试集 614 帧中 544 帧只有 1 个 GT（66 帧为 0，仅 4 帧为 2），50 个序列里 47 个全程单目标。用 0.3 阈值时只剩 2 条轨迹、6 个样本，lt16 桶为空。改为：**相邻帧均为单目标时关联唯一、直接接续**；仅多目标帧才走 IoU 阈值（全部 490 次关联中只有 1 次来自 IoU 路径）。0.2/0.3/0.5 三档敏感性照跑，轨迹数与各桶样本数同向（47 条 / lt16 128–132 个框对）。
2. **raw BJ 在本数据集结构性退化，与 gap 大小无关**：轨迹内相邻可用帧的编号差中位 6（分布 1–51），仅 51 对为 gap==1。直接量 GT 运动：**gap==1 的 51 对里，GT 自身框 IoU 中位 0（72.5% 完全无重叠），归一化中心位移中位 1.95 倍等效边长**。也就是说文件名相邻并不等于 25 fps 下的时间相邻，物体在两次采样间的位移普遍超过自身尺度。因此 `1−IoU(P_t,P_{t+1})` 在 4 个桶、所有 gap 上恒为 1.0，无任何区分力。
   改为 **GT 位移补偿口径**：把 `P_t` 按 GT 的中心位移与尺度比搬到 `t+1` 帧坐标（`warp_box`，只用 GT 运动、不用预测位移，避免把预测漂移吸收掉），再算 `1−IoU(warp(P_t), P_{t+1})`。理想模型下该值趋 0。
   同时保留 `BJ_gap1`（仅 Δidx==1 的 pair）作为严格定义下的参考列，实测同样恒为 1.0。
3. 因此报告口径固定为：**BJcomp 为主、CFR 与 σ_seq 并列、raw BJ 只作"退化说明"**。`BJ` 字段仍保留在 JSON 中，标注为不可用。
4. **论文里必须写清**：本数据集为抽样帧，任何"相邻帧框 IoU"型指标都会退化；本文用的是 GT 运动补偿后的残差抖动，等价于"扣除真实运动后的定位残差"。
