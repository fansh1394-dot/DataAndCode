# B1 改造方案：融合头双坐标系监督

**目标**：让融合头在 RGB 失效时能切换到 IR，恢复兜底能力。
**依据**：`困难子集评估报告·融合鲁棒性分析.md` 第六节（三项诊断）。
**日期**：2026-09-26

---

## 一、问题回顾（一句话）

融合头在 509 帧「RGB 失效」场景下 mAP50-95 仅 **0.0011**，而可用的 IR 分支有 **0.5760**。
诊断证明：融合颈的**权重与激活都没有偏废 IR**，但一旦 mask 掉 RGB 半边，融合输出**立刻归零**。

**机制**：融合头把 IR 当作「RGB 坐标系下的辅助线索」使用，而非独立检测依据。
根因（6.3）：**融合头从未被要求「在 IR 坐标系下也输出正确框」**。

---

## 二、核心设计思路

### 2.1 关键约束：两模态坐标系不同，不能简单混用

```
bboxes     : RGB 图的归一化框（RGB 坐标系）
bboxes_ir  : IR  图的归一化框（IR  坐标系）
```

Anti-UAV300 实测两模态归一化中心偏差中位 **3.62 pp**、最大 **10.85 pp**。
所以**不能**像某些朴素做法那样「把两套框拼在一起当正样本」——
这会让融合头收到互相矛盾的监督信号，正是 `prepare_mm_dataset.py` 丢弃困难帧
所要回避、也是本报告第二部分强调「不可用于训练」的那个陷阱。

### 2.2 方案：融合头「双坐标系并行输出 + 一致性约束」

**不用**拼接标签，而是给融合头加**第二条输出通路与第二条监督流**：

```
                 ┌──────────────────────────────────────┐
   fuse 特征  ──►│  fuse 检测头（原有，RGB 坐标系监督）  │──► 主输出（推理用）
                 ├──────────────────────────────────────┤
                 │  fuse_ir 检测头（新增，IR 坐标系监督）│──► 辅助输出（仅训练）
                 └──────────────────────────────────────┘
```

**三条约束**：

| 编号 | 约束 | 作用 |
|---|---|---|
| **L1** | `fuse` 头 ↔ `bboxes`（原有，不变） | 保持主路径性能不退化 |
| **L2** | `fuse_ir` 头 ↔ `bboxes_ir`（**新增**） | 强制融合特征在 IR 坐标系下也「独立成立」 |
| **L3** | `fuse` 与 `fuse_ir` 的预测框互为对方坐标系的一致性（**新增**，见 2.3） | 防止两通路各学各的、互不相干 |

**为什么这样能解决问题**：L2 让梯度必须穿过融合颈去拟合 IR 坐标系的框。
由于 `fuse_ir` 头与 `fuse` 头**共享同一份融合特征**（见 2.4），
融合特征被强制编码「IR 视角下目标在哪」的信息——
当 RGB 半边失效时，这部分信息仍可支撑融合头输出。

### 2.3 L3 一致性约束的必要性与实现选择

仅加 L2 有一个风险：融合特征可能被撕裂成「两块互不影响」的表示
（RGB 半边喂 fuse 头、IR 半边喂 fuse_ir 头），退化成"两个单模态头缝合"。

**L3 的作用就是阻止这种撕裂。** 两种可选实现：

| 实现 | 做法 | 评价 |
|---|---|---|
| **L3-a（推荐）** | 对同一目标，要求 `fuse` 头在 RGB 坐标系的预测 与 `fuse_ir` 头在 IR 坐标系的预测，**经坐标变换后**指向同一物理目标 | 语义正确，但需标定两相机变换矩阵 |
| **L3-b（备选）** | 对**双模态可见**帧，要求两通路预测框经各自标签归一化后**趋于一致** | 无需标定，用标签自身做变换，实现简单 |

**建议先用 L3-b**：因为 `bboxes` 与 `bboxes_ir` 的对应关系在数据里已经给出
（同一目标的两种表示），可以直接建立「RGB 框 → IR 框」的映射，
无需额外标定。L3-a 留作后续精细化。

> **重要**：L3-b **只在双模态可见帧上生效**。困难帧只有一个真值源，
> 无法建立两坐标系的对应关系，故不参与 L3。

### 2.4 参数共享策略

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **共享权重（推荐首试）** | `fuse_ir` 复用 `fuse` 头的卷积权重，只换输出层（reg/cls 头） | 参数少，强制共享表示，天然抗撕裂 | 输出层需独立 |
| 完全独立 | 两套完整头 | 灵活 | 参数翻倍，易各自退化 |

推荐**共享 backbone/neck 侧卷积、独立输出头**：
即 `fuse_ir` 就是一个新的 `Detect` 实例，但其输入特征与 `fuse` 完全相同，
且（可选）初始化时从 `fuse` 复制权重。

## 三、逐文件改造清单

### 3.1 `ultralytics/nn/mm/dual_head.py`

**改动**：`DualHeadFusionDetect` 支持第 4 个可选头 `fuse_ir`。

```python
class DualHeadFusionDetect(nn.Module):
    def __init__(
        self,
        rgb_detect: nn.Module,
        ir_detect: nn.Module,
        fuse_detect: nn.Module,
        fuse_ir_detect: Optional[nn.Module] = None,   # 新增：IR 坐标系辅助头
        branch_order: Tuple[str, ...] = ("rgb", "ir", "fuse"),
    ) -> None:
        ...
        # 注册为子模块，使参数被优化器收录（None 时不注册）
        self.fuse_ir_detect = fuse_ir_detect
        self._branch_modules = {
            "rgb": self.rgb_detect,
            "ir": self.ir_detect,
            "fuse": self.fuse_detect,
        }
        if fuse_ir_detect is not None:
            # 推理分支顺序不变（fuse_ir 不参与推理），仅追加到训练损失分支
            self._branch_modules["fuse_ir"] = self.fuse_ir_detect

    @property
    def train_branch_names(self) -> tuple:
        """参与损失计算的分支（含可选的 fuse_ir）。"""
        return tuple(self._branch_modules.keys())

    def forward(self, x):
        """x 长度 3（原样）或 4（含 fuse_ir）。"""
        ...
        return dict(zip(self.train_branch_names, x))
```

**兼容性要求（关键）**：
- `branch_order` 保持 `("rgb","ir","fuse")`，**推理路径完全不变**，
  已有 `best.pt` 仍可正常加载与预测。
- `fuse_ir_detect=None` 时行为与改造前**逐位一致**（默认关闭，保证 A0-2 可复现）。

### 3.2 `ultralytics/nn/mm/dual_loss.py`

**改动 1**：`BRANCH_LABEL_KEYS` 增加 `fuse_ir`。

```python
BRANCH_LABEL_KEYS = {
    "rgb":     ("bboxes",    "cls"),
    "ir":      ("bboxes_ir", "cls_ir"),
    "fuse":    ("bboxes",    "cls"),        # 主坐标系（推理用）
    "fuse_ir": ("bboxes_ir", "cls_ir"),     # 新增：IR 坐标系辅助监督
}
```

**改动 2**：`DualHeadDetectionLoss.__init__` 用 `head.train_branch_names`
而非 `head.branch_order`，使 `fuse_ir` 自动获得独立 criterion。

```python
self.branch_names = list(getattr(head, "train_branch_names", head.branch_order))
```

`loss_items` 长度会从 9 变成 12。**注意**：`val.py` 的校验逻辑需同步
（见 3.5，这是本改造最容易漏的一环——正是 A0-2 崩溃的同源问题）。

**改动 3**：`DualHeadFusionCriterion` 新增 `fuse_ir` 一致性项（L3-b）。

```python
def __init__(self, ..., ir_consist_weight: float = 0.0, ...):
    self.ir_consist_weight = float(ir_consist_weight)

def forward(self, preds, batch):
    det_loss, det_items = super().forward(preds, batch)
    ...
    # ---- L3-b：fuse 与 fuse_ir 的跨坐标系一致性（仅双模态可见帧）----
    if self.ir_consist_weight > 0 and "fuse_ir" in preds:
        consist = self._cross_coord_consistency(
            preds["fuse"], preds["fuse_ir"],
            batch["bboxes"], batch["bboxes_ir"],
        )
        extra = extra + consist * self.ir_consist_weight * batch_size
```

`_cross_coord_consistency` 的实现要点：
1. 用 `bboxes`/`bboxes_ir` 建立「同一目标」的配对（依赖 `batch_idx` /
   `batch_idx_ir` 的帧级对齐——注意这两者**索引口径不同**，需按帧分别配对）
2. 只保留**两模态都标到目标**的帧，困难帧跳过
3. 对 `fuse` 头输出按 `bboxes` 解码、`fuse_ir` 头输出按 `bboxes_ir` 解码，
   比较两者**归一化后的框**（因坐标系不同，比较应在归一化空间做，
   误差即两模态视场偏移的残差）

**改动 4**：`_head_consistency` 目前硬编码 `("rgb","ir","fuse")`，
若纳入 `fuse_ir` 需同步改（**建议先不动**，避免一次改太多变量难以归因）。

### 3.3 `ultralytics/nn/tasks.py`

**改动**：`parse_model` 支持第 4 个 Detect 的构建与 `DualHeadFusionDetect` 的 4 参数实例化；
`init_criterion` 传入新参数。

```python
return _DHFC(
    self,
    branch_weights={...,
        "fuse_ir": float(getattr(args, "mm_dual_w_fuse_ir", 0.0) or 0.0),
    },
    dfs_weight=...,
    ir_consist_weight=float(getattr(args, "mm_ir_consist_weight", 0.0) or 0.0),
    ...
)
```

### 3.4 `ultralytics/cfg/models/mm/detect/yolo11/base/yolo11n-mm-dual-fusion.yaml`

**新增**：融合分支的第 4 个 Detect 层，输入与 fuse 头**完全相同**的融合特征。

```yaml
# 融合主头（RGB 坐标系）—— 原有，不动
- [[46, 48, 50], 1, Detect, [nc]]              # 层 52: fuse_detect

# 新增融合辅助头（IR 坐标系）
- [[46, 48, 50], 1, Detect, [nc]]              # 层 53: fuse_ir_detect

# 聚合头：由 3 输入改为 4 输入（受开关控制）
- [[49, 51, 53, 54], 1, DualHeadFusionDetect, [nc]]   # 层 54
```

> **注意**：具体层号需按改造后的 YAML 重新计算，并同步更新
> `DualHeadFusionDetect` 的输入列表长度校验（当前硬校验 `len(x) == 3`，
> 需放宽为 3 或 4）。

**另建配置文件**而非原地改 `yolo11n-mm-dual-fusion.yaml`，
建议命名 `yolo11n-mm-dual-fusion-b1.yaml`，保证 A0-2 可原样复现。

### 3.5 `ultralytics/models/yolo/detect/val.py` 与 `ultralytics/nn/mm/dual_val.py`

**改动**：`DualHeadDetectionValidator` 的 `branch_names` 应只含推理分支
`("rgb","ir","fuse")`，**排除** `fuse_ir`（它只用于训练监督，不参与评测）。

**验证**：`loss_names` 长度需与 criterion 的 `loss_items` 长度一致
（3 分支 × 3 项 = 9 → 4 分支 × 3 项 = 12）。
**这是 A0-2 崩溃的同源位置，改造后必须逐项核对，否则会重现 9≠3 的校验失败。**

### 3.6 `train_full.py` / 参数注册

新增 CLI 参数并注册到 hyperparameter 体系：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--mm-fuse-ir` | `False` | 启用 fuse_ir 辅助头（总开关） |
| `--mm-dual-w-fuse-ir` | `0.5` | L2 损失权重 |
| `--mm-ir-consist-weight` | `0.1` | L3-b 一致性权重 |

**默认全部关闭**，保证现有 A0-2 行为不变。

## 四、实施顺序（降低归因难度）

| 阶段 | 内容 | 验证标准 |
|---|---|---|
| **B1-0** | 仅加开关与配置骨架，`fuse_ir=None` | 主集三路 mAP 与 `best.pt` **完全一致**（回归测试） |
| **B1-1** | 加 `fuse_ir` 头 + L2 监督（不加 L3） | 训练可跑；困难子集 A 组 fuse **应 > 0.1**（当前 0.0011） |
| **B1-2** | 加 L3-b 一致性约束 | A 组 fuse 进一步提升；主集性能**不退化** |
| **B1-3** | 消融 `ir_consist_weight ∈ {0, 0.05, 0.1, 0.5}` | 找到最优权重 |

**每阶段都必须跑困难子集评测**，用同一套脚本（`eval_hard_subset.py --groups`）
与 `best.pt` 基线对比。

## 五、风险评估

| 风险 | 可能性 | 应对 |
|---|---|---|
| 主集性能退化（为了 IR 鲁棒性牺牲 RGB 精度） | 中 | 控制 `mm_dual_w_fuse_ir`，从 0.3 起调；监控主集 fuse mAP |
| 融合特征被撕裂成两个独立通路 | 中 | 这正是 L3 要防的；若 L3-b 无效，改用 L3-a |
| 困难帧极少（A 组仅 509 帧，占训练集极少比例） | **高** | **见第六节：需配合困难帧增广** |
| 改造破坏已有权重加载 | 低 | 默认关闭 + `branch_order` 不变，可保证兼容 |

## 六、配套措施：困难帧监督数据

**这是 B1 能否成功的关键前提。** 当前训练集**完全不含**单模态可见帧
（`prepare_mm_dataset.py` 丢弃了它们），因此：

> 即使 B1 给了融合头「在 IR 坐标系下成立」的监督，
> 它也**从未在「RGB 失效」的样本上被训练过**——
> 因为训练集里根本没有这种样本。

### 建议做法

**不能**直接把困难子集的标签（单真值源同时写入 `labels/` 与 `labels_ir/`）
拿来训练——报告第二部分已说明这会污染坐标系。

**正确做法**：为困难帧补**真实的双坐标系标签**：
- 仅 IR 可见帧 → `bboxes_ir` 用真值；`bboxes` 应标注为「该目标在 RGB 中不可见」
  （当前机制已用「坐标 (>1) 或空」表达，见 `_prepare_targets` 的空目标处理）
- 具体实现需确认数据生成侧如何表达「某模态无目标」这一状态

| 方案 | 做法 | 成本 |
|---|---|---|
| **S1（推荐）** | 扩展 `prepare_mm_dataset.py`，保留困难帧并正确写入「单侧为空」的标签 | 中，需改数据生成 |
| S2 | 用 `copy_paste` / 模态 dropout 在线增广模拟模态失效 | 低，但引入伪标签噪声 |
| S3 | 不补数据，只做 B1 架构改造 | 最低，但预期效果有限 |

**建议 S1 + S2 组合**：S1 提供真实困难样本，S2 提升鲁棒性的泛化。

## 七、预期结果与判据

**成功判据**（困难子集 A 组，509 帧，基于同一 `eval_hard_subset.py --groups`）：

| 指标 | 当前（`best.pt`） | B1 目标 | 理想 |
|---|---|---|---|
| A 组 fuse | 0.0011 | **> 0.1** | > 0.3 |
| A 组 ir（不应变差） | 0.5760 | ≥ 0.55 | ≥ 0.57 |
| 主集 fuse mAP50-95 | 0.6997 | ≥ 0.69 | ≥ 0.70 |

**明确可写入论文的两种结果**：

1. **B1 有效** → 证明「融合头缺独立坐标系监督」是主因，
   形成「诊断 → 归因 → 改造 → 验证」的完整闭环，是论文的核心贡献。
2. **B1 无效** → 说明问题比监督层面更深（可能需结构改造，如 B2 门控融合），
   同样是有价值的边界结论，且三项诊断仍成立。

**两种结果都可报告**，不存在"白做"的风险——这正是先做零成本诊断的价值。

## 八、与 A0-3 的关系

**建议跳过 A0-3**（关闭 DFSC）。理由见报告 6.4：

- 诊断三证明融合颈权重**没有被偏废**，DFSC 不是直接瓶颈
- A0-3 大概率复现当前结果，用训练成本换取一个排除性证据
- 若后续 B1 有效，可再回头跑 A0-3 作为补充消融（此时它的意义变成
  「排除 DFSC 与 B1 的交互作用」）

**若仍需 A0-3**：它是**单参数改动**（`--mm-dfs-weight 0.0`），
成本不高，可作为 B1 训练期间的并行对照。
