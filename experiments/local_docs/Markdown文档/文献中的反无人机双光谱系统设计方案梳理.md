# 文献中的反无人机双光谱系统是怎么设计的

> 说明：本文只依据项目文献库中的现存文献与项目自身实测记录撰写，凡涉及具体参数、指标的地方均标注出处。凡属本文的分析与推论，均明确标为"分析"或"推论"，不与文献原述混淆。

## 一、先分清三件事：器件、算法、系统

读文献时最容易混淆的，是"双光谱系统"这个词在不同论文里指的完全不是一回事。按设计层次拆开看，可归为三类：

| 层次 | 文献在那里解决什么 | 典型代表 |
|---|---|---|
| 器件与成像 | 两路相机怎么装、怎么标定、怎么保证同步 | Huang 2026（未配准成像成因）、Jiang 2024（小目标配准）、赵庭辉 2026（位置对齐双相机） |
| 算法与网络 | 两路特征在哪一层、以什么方式融合 | 张天乐 2026（分层融合）、Tian 2023（RIFuse）、Wang 2022（冗余抑制）、Lu 2025（照度感知） |
| 系统与闭环 | 相机怎么指向、多机怎么协同、告警怎么形成 | Tegler 等（PTZ + 广角组网）、Liu 等（30 相机阵列）、Xu 2024（全景 + 三轴云台）、张鹏 2022（光电侦察链路） |

大多数论文只做中间一层。真正把三层都做通的，在项目文献库里极少。这也是本课题选题的空间所在。

## 二、器件层：两路相机是怎么配起来的

### 2.1 未配准是常态，不是例外

Huang 等（Drones, 2026）在引言里把未配准的成因列得很清楚，共三条：两路传感器成像时刻难以精确同步、镜头焦距调整导致图像尺度不一致、相机抖动与机械安装误差造成光心相对角偏差。他们同时给出一张同一无人机在两路图像中位置与尺寸都不相同的对比图【_lit/127.txt】。

这一条对系统设计的直接含义是：**共载不等于共视**。即便两路相机装在同一吊舱上，输出仍然是两幅没有像素级对应的图。任何默认"输入已配准"的融合网络，在真实吊舱上都会失效。

### 2.2 配准被作为检测前的显式模块

现有工作基本不指望网络自己学会配准，而是把配准做成独立前置步骤：

- **Huang 等 2026**：SURF 提特征 → 灰度质心法剔除误匹配 → 平面自适应像素重映射（plane-adaptive pixel remapping）得到融合图 → 增强 YOLOv11 检测。这是一个严格的"先配准、后融合、再检测"两阶段框架。
- **Jiang 等 2024**：面向可见光与红外小无人机目标，提出多级交叉注意力配准方法，并用图像风格迁移缓解两个模态之间的外观差异。其针对的正是小目标配准这一未解难点。
- **赵庭辉等 2026（《机器人》）**：其自建 M3Track 数据集用两架大疆 Mavic 3 Enterprise，每架配备**位置对齐**的可见光与红外相机同步采集，20 个场景、10 万对图像、112.9 万个目标，拍摄距离覆盖约 5 m 到 40 m。

这里有一个值得注意的分野：**近距离、结构对称的平台（如无人机载双光吊舱）可以做到"位置对齐"；远距离、塔架式固定部署则做不到**。赵庭辉的数据集距离是 5～40 m，本课题是 50～500 m，量级完全不同。直接把前者的对齐结论挪过来是不成立的。

### 2.3 配准的现存缺陷

项目文献综述归纳了三条：低纹理天空、热背景接近或目标极小时缺少稳定对应点；单一平面单应无法解释近距离目标、变焦与场景深度带来的视差；配准评价多停留在视觉叠加或平均误差，未直接关联检测召回率。

本课题实测的数据可以补一条实证：在 uav_data_v2 的 `both` 帧上，两路归一化框中心差 `mean|dx|≈0.030~0.039`、`mean|dy|≈0.074~0.080`，`max|dx|` 达 0.74。这不是几像素的抖动，而是接近四分之一个画幅的错位。

## 三、算法层：融合到底放在哪里

### 3.1 三层融合的取舍

文献共识是分像素级、决策级、特征级三档。像素级实现简单但对配准误差极敏感；决策级分别跑两个检测器再加权融合，工程稳定但丢掉细粒度互补；特征级在两个编码器中间层交互，是目前的主流折中。

对本课题的推论：既然实测错位可达 0.74 个归一化画幅，像素级融合在物理上就不成立。这也是本课题选择"放弃图像级配准、在特征层做对应"的直接依据。

### 3.2 分层融合的代表做法：张天乐等 2026

张天乐等的方案结构最完整，且与本课题的骨架高度接近，值得逐项对照：

- **基础模型**：YOLO11n，与项目现用一致
- **双骨干**：可见光与红外各自独立提取多尺度特征
- **HCF（Hybrid Cross-modal Fusion）分层混合融合**：
  - 浅层 P2、P3 用 `LiteCrossAttentionFusion`——自适应平均池化压缩 + 1×1 卷积映射到 Token + 双向交叉注意力 + 空间重建 + 门控增强（采用 `F ⊙ (1+G)` 而非 `F ⊙ G`，以保原始响应不过度抑制）
  - 深层 P4、P5 用 `StableConcatFusion`——通道拼接加线性映射，保障语义稳定
- **DBSPPF**：替换 SPPF，双分支多尺度池化增强深层上下文
- **四尺度检测**：增设 P2 头，构建 P2–P5
- **自建双模态数据集结果**：精确率 98.83%、召回率 93.18%、mAP@0.5:0.95 达 53.40%、参数量 4.84 M、计算量 8.3 GFLOPs、71.35 FPS

其设计动机写得很明确：现有方法"多采用统一式跨模态交互或简单拼接，未能有效区分浅层细节特征与深层语义特征在融合中的功能差异"。这句话正好解释了本课题为什么在融合颈上反复失败——本项目的融合颈对各尺度用的是同一套算子。

**但要注明两点差异**：其一，该文自建数据集，未见公开其采集距离与视场；其二，其指标是在自有数据上取得，不能直接与本课题的 uav_data_v2 结果横比。

### 3.3 其他融合思路

- **RIFuse（Tian 等 2023）**：并行 CNN 与 Transformer 分层，CNN 取 RGB 局部特征、Transformer 取 IR 全局表示，再用多模态特征融合块整合。这是本课题"双流轻量骨干 + 跨模态融合"架构的直接来源。
- **冗余抑制（Wang 等 2022）**：指出跨模态冗余会削弱互补信息的利用，简单拼接会让模型重复学习相同背景而不是吸收热信息。
- **照度感知（Lu 等 2025）**：按成像条件调整融合路径，而不是对所有条件用同一套权重。
- **频率域路线（WaveMamba, ICCV 2025；Dong 等 2026）**：小波分解后按频段做跨模态互补。表达能力较强，但算子在 RK3588 上的支持情况需重新评估，本课题不宜一开始就堆进主模型。
- **不配准直接检测（RTM-UAVDet）**：用多模态动态卷积从两路提特征，"无需进行图像配准"即实现实时检测。这条路线与本课题"不做图像级配准"的主张方向一致，可作为对照基线。
- **多光谱融合（MSF-Net）**：双流结构 + 多模态融合模块，处理可见光与多光谱数据。

### 3.4 单光谱分支的代表：Dual-YOLOv3-D

张鹏等的综述里收录了马旗等的"基于双通道的快速低空无人机检测识别方法"：5 万对可见光与红外双光图像，训练测试按 4:1 划分，提出 Dual-YOLOv3-D，针对三种机型相比原始 YOLOv3 的 mAP 提升 6.08%。这是早期"双通道 + YOLO"思路的代表，结构比现在的分层融合简单得多。

## 四、系统层：相机怎么协同、怎么指向

这一层最接近本课题要回答的问题，文献也最少。

### 4.1 广角组 + PTZ 的分工结构

王栋等（《中国科学基金》2026，第 40 卷第 1 期，双清论坛专题）的系统综述里，提到 **Tegler 等**设计的一种"具有良好扩展性的并行传感架构"，整合了三类设备：**麦克风阵列 + 固定广角摄像头组 + PTZ 云台相机**，用于对无人机目标的协同感知。

这是文献中与本课题"广角发现、长焦确认、多机接力"最接近的系统形态。其核心设计逻辑正是：固定广角负责铺开覆盖，PTZ 负责近距离精查，两者分工而非替代。**但该文未给出广角与 PTZ 的视场配比、切换时延和指向误差指标**——这些恰好是本课题要补的空缺。

### 4.2 大规模阵列与全景云台

- **Liu 等**：30 个高清摄像机 + 3 个麦克风的阵列系统，视频与音频分别提特征后再做多源融合，检测精度较单一特征方法显著提升。硬件装在轻量化机架上，便于部署。
- **Svanström 等**：可见光 + 热红外 + 音频三源融合，重点是鲁棒性与误检率下降。
- **Xu 等 2024**：360° 全景相机 + 三轴云台，用于大范围入侵检测与持续跟踪。
- **AcTrak（Fahim 等 2023）**：研究可控监视相机在"搜索新目标"与"放大跟踪既有目标"之间的策略切换——这说明扫描覆盖本质上是一个**资源调度问题**：搜索态要空间覆盖，确认态要像素分辨率，跟踪态要轨迹连续性，三者不能同时最大化。

这一结论对本课题至关重要。它把"长焦视场窄"从缺陷重新定义为**分工约束**：窄视场不是要修补的问题，而是确认态与搜索态必须分离的物理理由。

### 4.3 光电侦察链路的工程口径

张鹏等（《中国电子工业》类期刊，CAEIT 2022）从光电侦察角度梳理了检测流程：预处理抑制噪声与增强 → 图像分割分离目标 → 检测算法 → 借助序列图像信息、运动属性与上下文完成识别与连续跟踪。评价口径上，其收录的实测案例值得注意：

- 对城市 800 m、郊区 2300 m 两种场景，50～150 m 高度的机动无人机做检测试验，在无噪声、10 dB、20 dB 噪声下精度分别为 0.9927、0.9627、0.9581
- 不同天气（晴天、少云、多云、阴天）下误检率分别为 2.1%、10.9%、23.4%、3.4%
- 不同距离（50 m 到 2300 m）下目标峰值信噪比从 13.8 降到 1.3

**多云天气误检率 23.4%** 这个数字很值得引用——它说明背景复杂度对视觉系统的影响远大于噪声水平（20 dB 噪声下精度仍有 0.9581）。本课题在跨域评测中强调按场景拆解失效模式，依据就在这里。

## 五、把文献方案与本课题逐项对照

| 设计环节 | 文献中的主流做法 | 本课题的差异与理由 |
|---|---|---|
| 相机布置 | 双光吊舱共载，或 30 相机阵列，或全景 + 云台 | 三路近轴一体（广角 1.95 mm + 长焦 50 mm + 红外 19 mm），基线压到 ≤ 60 mm，500 m 处视差约 4.1 px |
| 视场分工 | 广角组 + PTZ 协同（Tegler），但未给配比 | 显式算出覆盖套数：广角 111° 覆盖 500 m 整圈需 25 套，红外 23° 需 72 套，单用长焦 6.4° 需 560 套以上 |
| 配准 | SURF + 灰度质心 + 平面重映射（Huang 2026）；多级交叉注意力（Jiang 2024） | 明确放弃像素级配准，改在特征层做局部偏移对齐、目标层做实例对应。理由是实测框中心差 |dx| 达 0.74 |
| 融合层级 | 浅层交叉注意力 + 深层拼接（张天乐 2026）；CNN-Transformer 分层（RIFuse） | YOLO11n 双流 + 三尺度融合颈 + 四检测头，融合算子 ≤ 0.3 M 参数，全部 RKNN 兼容 |

| 鸟机判别 | 外观分类（YOLOv9-AAG）；轨迹表征（Srigrarom）；Drone-vs-Bird 挑战赛 | 外观 + 热斑 + 运动三类正交证据，输出"无人机 / 鸟类 / 未知"三态开放集 |

## 六、文献暴露出的四个空白

**空白一：配准质量没有接进系统闭环。**
Huang 2026 把配准做成前置模块，但配准失败时检测仍然照跑，系统不知道自己已经失准。Jiang 2024 关注配准精度本身。没有人把配准残差作为质量分传给下游，用它来决定是否降级。本课题的 `q_reg` 设计正落在这里。

**空白二：系统论文不给覆盖账。**
Tegler 的广角组 + PTZ 架构、Liu 的 30 相机阵列、Xu 的全景云台，都描述了硬件构成，却都没有回答"这样配能覆盖多大空域、需要几套、视场交叠多少"。本课题把 `N = ⌈A/(S×k)⌉` 算成具体套数，这是一个可以补进文献的贡献点。

**空白三：模态失效被默认不存在。**
多数融合论文假设两路始终可用。Hu 等的统计指出公开数据集中只有很小一部分同时含红外与可见光；`only_ir` 帧数远多于 `only_rgb`（train 1277 vs 58），说明大量目标仅红外可见。真实系统必须能处理单模态输入，而现有融合网络普遍做不到。

**空白四：非对齐与热门开源生态是脱节的。**
GitHub 上星标最高的几个多光谱检测项目（CFT 480★、YOLOv11-RGBT 729★、YOLO-MIF 264★、DEYOLO 185★）全部假设两模态已配准；真正处理非对齐的星标都很低（DAMSDet 73★、CMAI-Det 10★、COXNet 9★、IM-CMDet 4★）。Huang 2026 这类工作也才刚刚出现。这说明"非对齐"在工程实践中是空白，不是已经解决的问题。

## 七、对本课题写作的三点建议

**第一，引文献时要引到"器件参数"这一层。**
只说"参考文献采用双光谱融合"没有说服力。要引到"Huang 2026 用 SURF + 灰度质心 + 平面重映射，说明未配准是常态"、"张天乐 2026 用 P2–P5 四尺度，参数量 4.84 M、8.3 GFLOPs、71.35 FPS，说明轻量化与四尺度可以共存"这种颗粒度。

**第二，诚实交代指标不具可比性。**
张天乐的 98.83% 精确率、53.40% mAP@0.5:0.95 是在自建数据集上取得的，采集距离与视场未公开；赵庭辉的 M3Track 是 5～40 m 的近距数据。本课题是 50～500 m、uav_data_v2 的 58,803 帧，两者不可横比。论文里必须写清楚这一层，否则会给人"不如人家"的错误印象。

**第三，把"空白"写成论证，而不是不足。**
本课题融合增益实测只有 +0.0074、drop-RGB 后 fuse 从 0.7148 塌到 0.0147，这不是失败，而是测出了一个文献尚未系统报告的现象：**在非对齐、非合作、模态会失效的三个真实条件下，现有融合架构的增益会退化到种子噪声区间**。开题时把这个结论讲清楚，比承诺"融合一定更好"更立得住。
