**学位论文**：对齐条件下的可见光—红外双光谱无人机目标检测。

- **数据**：Mendeley EO/IR 对齐数据集（原始 5,834 对帧）。两模态几何完全对齐、共用同一套标签；文件名 01–42 为真实拍摄，43–51 为人工合成；783 帧背景；99.3% 为单目标帧（双目标仅 41 帧）。

## 2. 技术架构

### 2.1 代码底座（已改为三头）

YOLO26 多模态分支（`MutilModel_3485988898`），共享骨干 + 非对称双流：

```
RGB ─┐
     ├─ 共享骨干（浅层）─ 分支（深层）─ 融合颈 ─┬─ rgb 头
IR  ─┘                                      ├─ ir 头
                                            └─ fuse 头（融合特征）
                    三个头由 DualHeadFusionDetectV26 聚合
```

- **三头改造已完成**（2026-10-28）：删除 `fuse_ir` 第四头。`labels_ir ≡ labels`（逐字节相同），双坐标系监督纯冗余。
  - `DualHeadFusionDetectV26.fuse_ir_detect` 改为 `Optional`，`None` 时行为与改造前**逐位一致**；
  - `dual_loss.py` 用 `branch_names = train_branch_names or branch_order` 自动裁剪到三支；
  - `dual_val.py` 仅在 `"fuse_ir" in train_names` 时才追加分支。
- 训练唯一入口：`train_v26.py`，白名单 `{v26-single-baseline, v26-dual-fusion-deform}`；**任意含 `/yolo26/` 的 YAML 路径也放行**（因此新配置无需改白名单）。输出强制 `YOLO26/ResTest/<name>`。
- 标签口径三态：`vis`（全部用 `labels`）/ `ir`（全部用 `labels_ir`）/ `dual`（rgb 用 `labels`、ir 用 `labels_ir`）。IR 单模态必须 `--single-modal x --label-from ir`。
- 配置目录：`ultralytics/cfg/models/mm/detect/yolo26/base/`
  - `yolo26n-mm-single-baseline.yaml`、`yolo26n-mm-dual-fusion-concat.yaml`、`yolo26n-mm-dual-fusion-deform.yaml`、`early/mid/late`
  - **`yolo26n-mm-dual-fusion-align3h.yaml`**（三头 + 位移置零，对齐原生）
  - **`yolo26n-mm-dual-fusion-part3h.yaml`**（三头 + ChannelPartitionFusion，本轮新增）

### 2.2 融合算子族

| 算子 | 形式 | 位置 | 状态 |
|---|---|---|---|
| `DeformableCrossModalFusion`（M3 在用） | K 点可变形采样 + 内容注意力 + 门控残差 | `ultralytics/nn/mm/deform_fusion.py` | 已训 150 轮；`max_offset<=0` 时走恒等短路 |
| `GatedReliabilityFusion` | `rgb + g·(ir−rgb)` | `ultralytics/nn/mm/gated_fusion.py` | 未训；gate 可整体趋 0 |
| `ReliabilityAwareFusion` | 凸组合 `w0·rgb + w1·ir` | `ultralytics/nn/mm/reliable_fusion.py` | 未训；融合不可能超过较强模态 |
| `ChannelPartitionFusion`（D3） | 输出通道硬切 `[RGB专属 \| IR专属 \| 交互]` | `ultralytics/nn/mm/partition_fusion.py` | 已构建校验，训练已排队；带 `_mm_force_ir` 诊断开关 |
| `CGAFusion` | 空间+通道+像素三级注意力 | `ultralytics/nn/modules/fusion/cgafusion.py` | 未接入主配置 |
| `TransformerFusionBlock` / `CrossTransformerFusion` | 交叉注意力 | `mm/modules/fusion/icafusion.py`、`ctf.py` | 未接入主配置 |

**算子签名与解析**（改 YAML 前必读）：

- `ChannelPartitionFusion(inc, ouc, max_offset=0.08, base="rgb", split=(0.5,0.25,0.25), num_points=4, attn="channel")`
- YAML 参数顺序（`tasks.py` L4306–4317 已注册）：`[ouc, max_offset, base, split, num_points, attn]`
- 通道切分为**向下取整 + 交互段兜底**：`n_rgb=round(ouc*0.5)`、`n_ir=round(ouc*0.25)`、`n_mix=ouc-n_rgb-n_ir`；`n_ir<1` 直接报错（防止配置等于放弃 IR 通路）。

### 2.4 评测口径（冻结，不得漂移）

- 域内只用 `test`（614 帧，含 flight 380 / indoor 28 / ground 33 / synthetic 118 / background_only 55）；`val` 只用于早停与选模型，**数字不得写进结论**。
- 模型必须分路报告 `rgb / ir / fuse`；**四头旧模型也不再列 `fuse_ir`**（三头改造后口径统一）。
- 融合增益**只引用 `fuse − rgb 头`**（同骨干同训练，最干净）；`fusion_gain_over_ir` 非独立指标，禁用。
- 额外给出 `fuse − max(M1,M2)`（模态互补性）与 `rgb 头 − M1`（共享骨干容量分流代价）。

### 2.5 对齐数据假设（本轮新增，直接影响所有训练）

三处「设计假设 vs 实际数据」错配已落盘修正：

1. **可变形 offset 分支**：数据已配准，非零位移只会引入双线性插值的低通损失。`deform_fusion.py` 在 `max_offset <= 0.0` 时走短路分支——不预测位移、不做 `grid_sample`、注意力取均匀权重，`fuse = rgb + gate*(ir - rgb)` 退化为纯门控。诊断量 `last_deform_spread` 同步置 0。
2. **`fuse_ir` 第四头**：`labels_ir ≡ labels`，双坐标系兜底无意义 → 三头化（见 2.1）。
3. **`mm_x_non_geo_*` 单侧非几何增强**：会破坏像素级对齐 → `data.yaml` 新增 `align: true`，`dataset.py` 在 `super().__init__` 前拦截：若 `align: true` 且 hyp 开启 `mm_x_non_geo_enable` / `mm_rgb_albu_enable`，直接 `ValueError` 拒绝训练。

| L48 | 2.44E+0 | 2.17E+0 | **0** | **8.90E−08** | 1.87E+0 | 4.47E+0 |

`offset` 梯度**严格为 0**（`max_offset=0` 的必然结果）；`attn` 非零但比其它子模块低 **7–9 个数量级**，工程上等同于不学习。

### 5.2c M0 是本项目最简融合（零自定义代码）

M0 的融合节点用的是 ultralytics 原生 `Concat` + 原生 `Conv`，**自定义代码 0 行**，`parse_model` 走标准分支。
对比：`ReliabilityAwareFusion` 82 行 / `GatedReliabilityFusion` 121 行 / `DeformableCrossModalFusion` 232 行 / `ChannelPartitionFusion` 237 行 / `CGAFusion` 91 行 / `CrossTransformerFusion` 380 行。
**约 1,500 行自定义融合代码（41 个模块），没有一个超过 0 行代码的 Concat（0.7645）→ M0 是强基线，不是弱基线。**

### 6.6 part3h 在 ep20 的 OOM 中断与续训（2026-10-28）

**现象**：14:28:49 训练进程退出，`ps` 无 `train_v26.py`，`results.csv` 停在 ep21 行（即 ep0–20 已完成）。

1. `cp -a last.pt last.pt.bak_stripped` 保留证据；

### 6.7 启用 B3 蒸馏时发现的三处阻塞缺陷（2026-10-29 已修）

启用 `--mm-dual-w-fuse-ir-distill 1.0` 本身不改代码，但链路上一路踩到三个坑，全部修复后首个实验才起跑成功。

**坑 1：M0 的融合节点无法被定位 → 屏蔽与蒸馏全部静默失效**

- 现象：`融合颈 RGB 屏蔽：未能从 DualHeadFusionDetect 反推出融合节点层`。
- 根因：`tasks.py` 的定位逻辑对 fuse 头输入**只回退一层**。deform/part3h 的融合节点正好是上一层（46→C3k2 47），能命中；但 M0 是「Concat → 1×1 Conv → C3k2」三层结构，回退一层只落到 1×1 Conv，判定失败。
- 修复：改为沿单输入链回溯最多 4 跳，遇到 `Concat` / 四个双光谱融合算子即停止（`_is_fusion_node` 闭包）。修复后 M0 正确识别为 `[46, 49, 52]`。
- 快照：`tasks.py.bak_maskloc`。

**坑 2：`DUAL_HEAD_CONFIGS` 缺 yolo26 配置 → 传蒸馏参数直接被拒**

- 现象：`指定了 --mm-dual-* 参数，但 --config 不是 dual-fusion / dual-fusion-b1`，exit=2。
- 根因：白名单只收录 YOLO11 时代的别名。`yolo26n-mm-dual-fusion-concat/align3h/part3h` 都使用 `DualHeadFusionDetectV26` 聚合三头，属真双头架构。历史训练从未传 `--mm-dual-*`，校验分支从未执行，缺口一直隐藏。
- 修复：把三个 yolo26 配置补进 `DUAL_HEAD_CONFIGS`。快照 `train_full.py.bak_dualcfg`。

**坑 3：命令行参数名是连字符而非下划线**

- `--mm_fusion_rgb_mask_p` / `--mm_dual_w_fuse_ir_distill` 均不被 argparse 接受。
- 正确写法：`--mm-fusion-rgb-mask`（无 `-p`）、`--mm-fusion-rgb-mask-scope`、`--mm-dual-w-fuse-ir-distill`。

**附带提醒**：`train_full.py` 会把屏蔽/蒸馏状态自动拼进 run 名（`-frm0.3` / `-frs` / `-dist1`），排队脚本的"已跑过"检查必须用通配前缀，不能按写死目录名匹配。
