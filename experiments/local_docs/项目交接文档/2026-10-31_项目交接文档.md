## 3. 关键技术实现细节

### 3.1 数据流总览

```
输入: 6 通道张量 (RGB 3ch + IR 3ch)
  ├─ RGB backbone (L0-L10, D=0.50/W=0.25)  → P3/P4/P5
  ├─ IR  backbone (L11-L21, 同构)            → P3/P4/P5
  ├─ RGB neck (L22-L33)  ┐
  ├─ IR  neck (L34-L45)  ┤
  └─ 融合颈 (L46-L54) ← Concat(RGB, IR) + 1×1 Conv 压回原通道
        ↓
  v26Detect ×4: rgb(27,30,33) / ir(39,42,45) / fuse(48,51,54) / fuse_ir(48,51,54)
        ↓
  DualHeadFusionDetectV26（零参数聚合，仅打包 dict）
        ↓
  推理：只走 fuse；训练：四路同时监督
```

**为什么 fuse_ir 与 fuse 共享同一组特征**：因为 `labels_ir ≡ labels`（IR 与 RGB 标签完全同源），
`fuse_ir` 只是「IR 坐标系下的辅助监督头」，不产生新的推理路径，因此不进入 `branch_order`。

### 3.2 三头聚合层的硬契约（改架构前必读）

```python
nls = {name: int(getattr(mod, "nl", 3)) for name, mod in self._branch_modules.items()}
if len(set(nls.values())) != 1:
    raise ValueError(f"DualHeadFusionDetectV26 要求各头的 nl 一致，实得 {nls}")
```

**后果**：任何「只给 fuse 分支加尺度/加头」的想法都会直接构建失败。
P2 实验因此必须**四条分支全部加 P2**（见 M13）。

`forward` 只做长度校验与打包，**不解包**：

```python
return dict(zip(self._branch_modules.keys(), x))
```

解包由 `one2many()` / `one2one()` 静态方法处理，兼容 v26Detect 的两种返回形态
（训练态 `dict`、推理态 `(y, dict)`）。

### 3.3 `parse_model` 的两条融合注册分支（最高频踩坑点）

| 分支 | 算子集合 | 通道处理 | YAML 应传 |
|---|---|---|---|
| 跨模态分支 | `CIDAF, CGAFusion, DAF, DynamicAlignFusion, WDAF` | `ouc = args[0]`，再 `make_divisible(min(ouc, max_channels) * width, 8)` | **未缩放**的 256/512/1024 |
| 纯特征融合分支 | `PIM, CMCE, WCMF, GFM, ...` | `len(args)==0` 时自动 `args[0]=c_left`，**不乘 width** | `[]` 最安全 |

**为什么会错**：这两条分支对 `args[0]` 的语义完全不同。传到错误分支会导致通道被二次缩放，
模型能建起来、能训练、loss 正常，但容量与对照组不可比 —— 是最隐蔽的一类错误。

### 3.4 对齐守卫（几何增强的唯一合法路径）

`data.yaml: align: true` → `ultralytics/data/dataset.py` **L648** 拦截所有单侧几何扰动：

```python
# 语义：任何会移动像素的单侧变换都必须被拒绝
if align and (mm_async_geo_p > 0):
    raise ...
```

因此 `degrees/shear/perspective/flipud` 在默认配置下**物理不可用**。
合法做法是**两模态施加同一组参数**（M12），像素对应关系不变。已验证：
`scripts/_verify_sync_geo.py` 冒烟通过，传入时生效值为 `10.0 / 5.0 / 0.0005`，不传时三个均为 `None`。

**例外（2026-11-02 新增）**：错位鲁棒训练（E9 / M22）**故意要破坏对齐**。做法是派生一份
`align: false` 的 `data.yaml`（`_d2p1/async_yamls/data_train_async.yaml`），**原文件不动**——
`align` 只在数据集初始化时被这一处守卫读取，没有其它行为分支，改这一位只解除拦截，不改变取图与标签逻辑。
配套参数：`--mm-async-geo-p / -translate-px MIN MAX / -rotate-deg MIN MAX / -target {x,rgb,random}`，
作用位置是 **letterbox 之后**的 640 空间（与错位退化曲线的 px 口径一致），且**不修改标签坐标**
（标签始终在 RGB 坐标系，这正是「学习容忍错位」的信号来源）。

> 实现期踩坑：`MultiModalAsyncPerturb.__call__` 调用了只在 `__init__` 内局部导入的
> `_scalar_to_border_value`，`p>0` 首次命中即 `NameError`（默认 `p=0.0` 掩盖了它，属死代码）。
> 已补一行导入，备份 `multimodal_augment.py.bak_20261102_asyncfix_srv`。

### 3.5 训练入口的两层封装

| 层 | 文件 | 职责 |
|---|---|---|
| 外层 | `train_v26.py` | 白名单（`V26_CONFIGS`）+ 断言：`--config` 必须含 `/yolo26/` 或在白名单；`--project` 强制 `YOLO26/ResTest`；`--resume` 只认该目录下 `last.pt` |

### 3.6 评测口径（所有 mAP 数字的唯一来源）

```bash
$PY -u scripts/eval_split.py --weights <best.pt> --data <data.yaml> --split test \
    --labels-mode dual --imgsz 640 --batch 16 --workers 4 --tag <tag> --out <json>
```

- **主指标**：`fuse` 分支的 mAP50-95
- **增益口径一**：`fuse − rgb`（本文用此定义，M0_concat = 0.7637 − 0.5707 = **+0.1930**）
- **增益口径二**：`fuse − max(单路)`（= 0.7637 − 0.6266 = **+0.1371**）
  ⚠️ 两个口径值不同，论文中必须统一并写明用哪一个，否则会被质疑自相矛盾
- **显著性**：`|Δ| > 2σ(0.0188)` 才算显著；单种子差值一律不作结论

**2026-11-02 新增两条口径**

| 口径 | 定义 | 实现 |
|---|---|---|
| 尺寸分桶 | GT 与检测框都按等效边长 `sqrt(w*h)` 分进同一桶（<16 / 16-32 / 32-64 / 64-128 / ≥128 px），桶内用 `ap_per_class` 算 mAP50 / mAP50-95 | `scripts/sizebucket.py`、`bucket_all.sh` |
| 错位扰动 | IR 半边整体平移 `dx,dy`（**640 输入空间 px**，内部按每帧 letterbox 比例换算回原图）与旋转（度，绕中心）；RGB 半边保持原样 | `eval_split.py --ir-shift / --ir-rotate` |

错位补丁与模态置零是同一套机制（monkey-patch `dataset.load_multimodal_image`，**必须在 `build_dataloader` 之前**），
并带自检断言：`RGB max|Δ|=0`、`IR mean|Δ|>0.1`，否则直接抛错——避免再次出现「静默 Δ=0」的假结果（X-08）。

### 10.5 实测数据

> 口径说明：所有板端测值都在**带 GUI 负载的非受控环境**下取得，仅作工程可行性证据，不作排行榜式对比。
> 「infer」= NPU 推理 + 主机前后处理；「e2e」= 从取到帧到产出检测框的完整延迟。

**A. 单帧推理性能**

| 模型 / 配置 | 平均延迟 | FPS | 体积 | 备注 |
|---|---|---|---|---|
| yolo11 6 通道（fp16） | **55.81 ms** | 17.92 | 7.47 MB | 基线闭环，验证 NPU 可用 |
| yolo26 v2（fp16，剥后处理） | **97.41 ms** | 10.27 | — | 崩溃已消除，但数值不可用（T5） |
| yolo26 v2（**int8**，calib160） | **64.06 ms** | **15.6** | 8.33 MB | 默认交付配置 |
| yolo26 v2（fp16 + 暴露 PSA） | 125 ms | 8.00 | — | 保精度备选，慢 |
| yolo26 剪枝 + int8 | **57.3 ms** | — | 9.35 MB | NPU 快 10%，**体积反而更大** |
| int8 + 板端解码（整链） | **78.57 ms** | **12.7** | — | 其中解码仅 **0.71 ms** |
| 视频流整链（1080p+640×512） | 75.55 ms (57.25+18.30) | 9.95 | — | e2e **251.95 ms** |

**B. 板端精度验收（40 帧 test 子集）**

| 口径 | mAP50 | Precision | Recall | mean IoU |
|---|---|---|---|---|
| ORT fp32（主机参考） | 0.8680 | — | — | — |
| **板端 int8（normal, calib160）** | **0.8899** | **0.8684** | **0.9167** | **0.8052** |

> 结论：int8 量化后板端 mAP50 **不低于** fp32 参考（+0.0219），说明量化误差未造成实质精度损失；
> 该子集仅 40 帧，**不能**替代全量 test 的 0.7637/0.7551 口径。

**C. 校准集规模（8 / 32 / 160）**

| 校准张数 | cos 相似度区间 | 板端 mAP50 |
|---|---|---|
| 8 | 0.9969 | 0.8899 |
| 32 | ~0.9980 | 0.9287 |
| 160 | 0.99924 | 0.8899 |

> 结论：三档差异属**噪声级**，校准集扩样无收益；默认取 160 张（覆盖昼夜/背景更稳）。

**D. 量化算法对比**

| 算法 | mean_abs 偏差 | 框 IoU（min） | 分数偏差 | 构建耗时 |
|---|---|---|---|---|
| normal（默认） | 基准 | 0.765 | — | **12.9 s** |
| mmse | **−45%** | **0.830** | **系统性 −0.12** | **8.8 min（×41）** |

> 结论：mmse 数值更好但分数系统性偏低且构建极慢 → **默认用 normal**，mmse 仅作消融记录。

**E. 剪枝 + int8 的代价**

| 项 | 未剪枝 int8 | 剪枝 int8 | Δ |
|---|---|---|---|
| 板端 mAP50 | **0.8899** | **0.7678** | **−0.12** |
| NPU 推理 | 64.06 ms | 57.3 ms | −10% |
| `.rknn` 体积 | 8.33 MB | 9.35 MB | +1.02 MB |
| 剪枝规模 | — | 60 单元：剪 22 / 保守跳过 38 | 累计剪 **816 通道** |

> 结论：**剪枝当前是负收益**（精度掉 0.12，速度只快 10%，体积还变大）。
> 蒸馏/微调恢复精度是启用剪枝前**必做**的一步，否则不建议上线剪枝模型。

**F. 视频流流水线（MPP 硬解 + ring cap=4 + 三线程）**

| 场景 | 帧数 | fps | infer | e2e | 出框 | 告警 | ring 投/覆/溢 |
|---|---|---|---|---|---|---|---|
| letterbox 1920×1080 + 640×512 | 58 | 9.95 | 75.55 ms | 251.95 ms | **58/58** | 3 | 59/0/0 · 59/0/0 |
| stretch 同源 | 58 | 10.01 | 74.01 ms | 252.52 ms | 58/58 | 3 | 同左 |
| 长跑 300 帧 | 299 | 10.02 | 75.73 ms | 253.13 ms | **299/299** | **10** | 299/0/0 · 299/0/0 |

- 预处理丢帧 **0**，采集失败 **0/0**。
- 告警 seq = 2/33/64/95/126/157/187/218/249/279，**间隔 31 帧 ≈3.1 s**（`--cooldown 3000`），1 条确认轨迹。
- 坐标反变换：letterbox（`scale=0.3333 pad_y=140`）与 stretch（`sx=0.3333 sy=0.5926`）对同一目标的框差 **≤5.3 px（<0.3% 帧宽）**。

**G. 阈值 ROC**

| 口径 | 最优点 | P | R | FPR | J |
|---|---|---|---|---|---|
| ORT 参考（Youden） | 0.15~0.25 | 0.882 | 0.833 | — | — |
| **板端（平台区）** | **0.05~0.30** | **0.9429** | **0.9167** | 0.0556 | 0.8611 |

**目标**：插上相机（或回放码流）后，直接在板子的屏幕上实时看到检测画面——
出现无人机即画框、触发告警即顶部红条闪烁，同时照旧落盘 `alerts.jsonl` 与证据帧。

**显示路径的选型（关键结论）**：板上显示栈是 **GNOME on Xorg，用户会话 `:1`**
（`Xwayland0 800x1280` 逻辑分辨率，唯一 connected 输出为 MIPI `DSI-1`），
零修改约束下既不能停止 Xorg、也不能抢 DRM master（会与 Xorg 冲突导致 page-flip 失败）。
因此**上屏走 X11 窗口（Xlib + `XPutImage`）**：在 `:1` 上开一个 override-redirect 窗口，
把自绘的 RGB888 帧缓冲逐行转 XRGB 后推给 X 服务器。
`libX11`/`libdrm` 均随系统已装，**全程只读 `/run/user/1000/gdm/Xauthority`，不改任何配置**。
裸 DRM dumb-buffer 后端保留为第二选择（X11 不可用时才尝试）。

**架构取舍：为什么是单线程串行**

`rk_ui_main` 最初是「采集线程 → 预处理线程 → 推理线程」的三级流水线（双缓冲交接）。
实测出现**交接僵死**（`raw.tag` 前进但 `prep` 收不到、`ring_try_newest` 恒返回 −1），
逐层排查（gdb 回溯、ASan、ring/cap 最小复现）确认是「消费方轮询 + 生产方拷贝持锁 +
条件变量唤醒丢失」的组合问题。最终改为**主循环单线程串行**：

```
采集线程（MPP/V4L2）──ring──▶ 主循环：取最新帧 → 预处理 → 推理 → 跟踪 → 画框 → 上屏
```

依据：单帧 NPU ≈ 60~75 ms、预处理 ≈ 22~39 ms，10 fps 相机（100 ms/帧）下串行
仍有吞吐余量，而串行版的延迟是确定的、不受调度抖动影响。**实测僵死消失。**

## 11. 兜底方案设计（标定误差 → 单模态退化）

### 11.1 为什么必须有兜底

错位退化曲线（§13.4，14 档实测，基线 fuse `0.7637`）给出三个**交叉点**：

| 错位量 | 融合 fuse | 对比单模态 | 结论 |
|---|---|---|---|
| 6 px | 0.5865 | **IR-only 0.6266** | 融合已**不如**只跑 IR |
| 8 px | 0.5384 | **RGB-only 0.5707** | 融合已**不如**只跑 RGB |
| 12 px | 0.4601 | **IR 置零 0.4862** | 融合已**不如**把 IR 整块丢掉 |

**问题本质**：融合头 `fuse` **没有自门控**。它训练时只见过「完美对齐」的输入，
一旦输入错位，两个分支的特征在通道维拼接后语义冲突，检测头无法自行判断该信谁，
于是**既不信 RGB 也不信 IR**，表现为比任一单模态都差。

而真实部署里，双光谱相机的标定误差通常做不到 ≤1 px。因此**必须在推理侧加外部门控**：
要么把模型训练成对齐不敏感（§11.8 的 `M0Async`），要么在错位超标时**主动降级**。

### 11.2 异常触发条件（三源融合判定）

降级不能只看一个指标，否则容易误触发。设计为「空间 + 时间 + 一致性」三源，任一硬条件成立即可降级：

| 编号 | 触发源 | 判据 | 阈值（建议） | 物理含义 |
|---|---|---|---|---|
| **TR1** | 空间：配准残差 | 同帧 rgb/ir 两头框中心位移（因果窗中位数） | `> 3.5 px` 抢跑 Async（2026-11-03 依据 §13.4 J-3/J-4；离线临界点 1.5 px 见 §13.4 E/F） | 标定漂移或视差超限 |
| **TR2** | 空间：相位相关 | PCE（峰值相关能量） | `PCE < 0.10`（连续 K 帧） | 两路图像**结构不匹配**（非单纯平移）。⚠️ 本数据集上未验证出可用性（§13.4 I），**不建议作主判据** |
| **TR3** | 时间：配对偏差 | `abs(ts_rgb − ts_ir)` | p99 **> 33 ms**（≈1 帧@30fps） | 采集不同步，运动目标产生等效错位 |
| **TR4** | 数据：缺模态 | 某一路连续丢帧 | 连续 **> 5** 帧 | 相机掉线 / 解码失败 |
| **TR5** | 模型：置信度塌陷 | `fuse` 最高分 vs 单模态最高分 | `max_fuse < max_ir − 0.15` 且持续 K 帧 | 融合分支已「自我怀疑」。⚠️ 2026-11-03 逐帧验证：置信度类指标对错位几乎不敏感（AUC 0.50，§13.4 J-1），**只能作补充确认** |
| **TR6** | 数据：饱和/遮挡 | 某路亮度直方图 >95% 像素在 [0,8] 或 [247,255] | 连续 10 帧 | 镜头被遮/过曝，该模态无效 |

**优先级**：TR4（缺模态）> TR1/TR3（硬错位）> TR2（软不匹配）> TR5（置信度）> TR6（质量）。
**TR5 是「事后指标」不是「事前指标」**——它只能作为补充确认，不能单独作为唯一触发，
否则会形成「越降级越自信」的正反馈。

### 11.3 降级状态机

四态，禁止跨态跳变（只能相邻迁移），保证不会在两种模态间高频抖动：

```
                 ┌─────────────── TR1/TR2/TR3 连续 K 帧 ───────────────┐
                 ▼                                                     │
   ┌──────────┐      ┌──────────┐      ┌──────────┐      ┌──────────┐  │
   │  S0      │      │  S1      │      │  S2      │      │  S3      │  │
   │ 融合主跑 │ ───▶ │ 降级预警 │ ───▶ │ 单模态跑 │ ───▶ │ 保持/停  │  │
   │ fuse     │      │ 双路并跑 │      │ IR 或 RGB│      │ 仅跟踪   │  │
   └──────────┘      └──────────┘      └──────────┘      └──────────┘  │
        ▲                  │                  │                  │      │
        └──── 恢复：连续 M 帧全部正常 + 迟滞 ───┴──────────────────┘      │
```

| 状态 | 行为 | 判定输入 | 退出条件 |
|---|---|---|---|
| **S0 正常** | 走 `fuse` 分支，`thr=0.25` | 三源全正常 | 触发 TR1/2/3/4 连续 K 帧 |
| **S1 降级预警** | `fuse` 与**选定单模态**并跑，**只在告警侧取单模态结果**；同时记录 `degraded=true` | 同上，但仅 K 帧 | 恢复正常 M 帧 → S0；继续恶化 → S2 |
| **S2 单模态** | 只跑选定单模态（省一半算力），`thr` 上调至 0.30（单模态精度低，需更保守） | 错位持续 | 恢复 M 帧 → S1 → S0（**不得直接回 S0**） |
| **S3 保持/停** | 两路都不可用（TR4 + TR6）→ 停止检测，仅保留跟踪外推与「设备异常」告警 | 缺模态 > 30 帧 | 任一路恢复 → S2 |

**参数**：`K = 5` 帧（约 0.25~0.5 s 确认，避免单帧噪声误触发）、`M = 30` 帧（约 1~3 s 恢复确认）、
S2→S1→S0 的两级回升是为了**防止在阈值附近来回摆动**。

### 11.4 单模态选择策略：默认 IR

有兜底能力的前提是**单模态头本身可用**。三个单模态分支都已在 test 上实测（§9.4）：

| 分支 | mAP50-95 | 相对 fuse 损失 | 选用建议 |
|---|---|---|---|
| **IR-only** | **0.6266** | −0.1371 | ✅ **默认降级目标**（白天/夜间都稳，受光照影响小） |
| RGB-only | 0.5707 | −0.1930 | ⚠️ 仅在 IR 通道故障（TR4）时启用 |
| IR 置零（fuse 走缺 IR） | 0.4862 | −0.2775 | ❌ 最差，仅作对照，不作为降级路径 |

**为什么 IR 优先**：
1. 绝对精度更高（0.6266 > 0.5707）；
2. 小目标信噪比更好（低慢小目标在红外上对比度更强）；
3. 模态置零实验显示 **IR 依赖（0.2775）> RGB 依赖（0.1896）**，IR 是主导模态；
4. 夜间场景 RGB 基本失效，而本课题的目标（低慢小无人机）恰恰常在夜间/逆光条件出现。

**切换规则的例外**：若 TR6 判定 IR 饱和/被遮（镜头遮挡、强逆光），则改选 RGB；
若两路都触发 TR6，进 S3。

### 11.5 迟滞与门控实现

**问题**：错位量往往是**连续变化**的（比如平台振动、云台漂移），如果用一个硬阈值，
会在阈值附近每帧来回切换，导致告警序列断裂、轨迹 ID 频繁重建。

**做法一：双阈值迟滞（Schmitt Trigger）**

| 方向 | 阈值 |
|---|---|
| S0 → S1（进入降级） | `h_rms > 1.5 px` 或 `PCE < 0.10`，连续 **K=5** 帧 |
| S2 → S1（开始恢复） | `h_rms < 1.2 px` **且** `PCE > 0.25`，连续 **M=30** 帧 |
| S1 → S0（完全恢复） | 再连续 **M=30** 帧满足上一条 |

进入与退出阈值之比为 **1.25 倍**（1.5 / 1.2），配合 K=5 与 M=30 的帧数迟滞共同抑制边界抖动。
阈值自 2026-11-03 起由 2.0 px 收紧到 1.5 px，依据是 §13.4 E/F 的三方向交叉点（竖向 1–2 px 即已反超）。

**做法二：相位相关 PCE 门控（事前指标，推荐主用）**

- 取两路**降采样灰度图**（如 160×160）→ 加 Hann 窗 → FFT → 互功率谱 → 逆 FFT 得相关面；
- 主峰 `PCE = peak² / (sum(其余) − peak²)`；主峰位置即当前平移量估计（**无需标定矩阵**）；
- 判据：`PCE < 0.10` 视为「结构不匹配」，此时即便平移估计很小也不可信（可能是尺度/旋转/遮挡）；
- **成本**：160×160 的 2D FFT 在 ARM A76 上约 **1~2 ms**，可每 5 帧跑一次（20 Hz 下 <0.5 ms/帧均摊）。

> 与训练侧的关系：`M0Async` 训练把「容忍度」搬到了数据分布（§11.8），
> 但**数据分布只能覆盖训练时见过的错位范围**，超出范围仍必须靠这里的外部门控兜底。

### 11.6 容错处理（工程侧）

兜底不只是「换分支」，还包括**输入不可信时的降级容错**：

| 场景 | 容错动作 | 实现位置 |
|---|---|---|
| 双路时间戳偏差过大（TR3） | 丢弃该配对帧，不降级；连续超 5 帧才进 S1 | `rk_stream.c` 配对队列 |
| 单路丢帧（TR4） | 用 ring 中最近帧**保持**（hold-last），最多 5 帧；超限进 S2/S3 | `rk_ring.c` + 主循环 |
| 配对失败 | 计入 `pair_drop`，**超过 2% 打印告警**，不静默 | `rk_alert.c` |
| 单应矩阵残差超限（TR1） | 该帧**不写告警文件**（避免污染证据链），只记 `degraded=true` | `rk_alert.c` |
| 某路分辨率变化 | 拒绝该帧并告警（训练口径固定 640×640 letterbox，尺寸突变意味着数据源变了） | `rk_pre.c` |
| 模型输出异常（全 0 / NaN） | 该帧判为无效，连续 3 帧进 S3 | `rk_model.c` |
| 降级期间 | 告警 JSON 必带 `degraded`、`pair_delta_ms`、`modality`、`h_rms` 四个字段，**事后可追溯** | `rk_alert.c` |

**告警记录字段（扩展后）**：

```json
{"seq": 33, "ts_ms": 1793481234567, "cls": 0, "score": 0.72,
 "bbox": [x1, y1, x2, y2], "track_id": 7,
 "modality": "ir", "degraded": true,
 "pair_delta_ms": 12, "h_rms": 3.4, "state": "S1"}
```

> 设计原则：**宁可少报，不可错报**。降级期间提高阈值、丢弃不可信帧，
> 换来的是「每一条告警都可复现、可归因」。

### 11.7 板端接入点（具体落点）

兜底逻辑**不需要改模型，也不需要改 RKNN**，只改运行时调度层。落点如下：

| 层 | 文件 | 改动 | 说明 |
|---|---|---|---|
| 采集 | `rk_capture.c` | 补 `fourcc`/MPLANE/驱动时间戳（§10.7 A1–A4） | 为 TR3 提供可信 `ts` |
| 配对 | `rk_stream.c` 主循环 | 新增**配对队列**（按 `ts` 最近邻，容差 1 帧） | 产出 `pair_delta_ms`、`pair_drop` |
| 门控 | **新增 `rk_gate.c/h`** | PCE 计算 + 迟滞计数 + 状态机 | 纯 C，无 OpenCV 依赖；FFT 可用 `kissfft` 单文件或自写 radix-2 |
| 模型 | `rk_model.c` | 支持**按状态切换输出分支**：`fuse` / `rgb` / `ir` 三套输出索引 | 单头导出时若只导 `fuse`，则 S2 需改用**置零输入**跑 `fuse`（次优，见 §11.4） |
| 告警 | `rk_alert.c` | 扩展 4 个字段；S1 期间丢弃不可信帧 | 见 §11.6 |
| 主控 | `rk_stream.c` | 按 `state` 调 `thr`（0.25 / 0.30）与分支 | 状态变更写 `run.log` |

**关键工程约束（必须提前决策）**：

- **导出形态决定兜底上限**。若 RKNN 只导 `fuse` 单头（当前做法，最省算力），
  则 S2 的单模态只能靠「把另一路置零喂给 fuse」，实测 **0.4862**，比真正的 IR 头 **0.6266** 差 0.14。
- **若要真降级到 IR 头**，必须导出**双输出**（`fuse` + `ir`）或**双模型**。
  双输出会增加 RKNN 图复杂度与内存，需重新做一次 T4–T6 验证（**未验证**）。
- **建议方案**：论文演示用「双模型」（`fuse_int8.rknn` + `ir_int8.rknn`），
  按状态加载/切换；工程上比双输出更稳，代价是内存翻倍（约 +8 MB，可接受）。

### 11.8 训练侧兜底：把容忍度搬到数据分布

工程兜底是「错位超标就降级」，训练侧兜底是「让模型见惯错位」。二者互补，不是替代。

**已完成的代码改造（2026-11-02）**：

| 层 | 文件 | 改动 | 备份 |
|---|---|---|---|
| 数据集 | `ultralytics/data/multimodal_augment.py` | 新增 `MultiModalAsyncPerturb`：letterbox 后 640 空间、**单侧**施加平移/旋转，`target=x` 即只动 IR，**不改标签** | `.bak_20261102_asyncfix_srv` |
| 训练入口 | `train_full.py` | 新增 5 个参数：`--mm-async-geo-p`、`--mm-async-geo-translate-px`、`--mm-async-geo-rotate-deg`、`--mm-async-geo-target`、`--mm-async-geo-border` | `.bak_20261102_async_srv` |
| 数据配置 | `_d2p1/async_yamls/data_train_async.yaml` | `data.yaml` 副本，`align: false`（**必须**，否则被对齐守卫拦截） | 新建 |
| 评测 | `scripts/eval_split.py` | `--ir-shift "dx,dy"` / `--ir-rotate` 度；`warpAffine` 单侧作用 3:6 通道，border 114 | `.bak_20261102_mis_srv` |

**异步扰动的设计取舍**：

| 决策 | 选择 | 理由 |
|---|---|---|
| 施加位置 | letterbox **之后**（640 空间） | 与评测口径一致，像素单位可直接对齐错位曲线 |
| 扰动幅度 | 平移 1–4 px、旋转 ±1° | 覆盖曲线中「损失 2~15%」区间，不引入图像外黑边伪影 |
| 概率 | `p = 0.5` | 一半样本保持完美对齐，避免模型退化为「只信单模态」 |
| 是否改标签 | **否** | 单侧扰动不改变目标真实位置（以 RGB 为基准），改标签会引入错误监督 |
| 是否两路都动 | **否**（`target=x`） | 两路同步动等价于普通几何增强，学不到「错位」这件事 |

**已验证（静态）**：`[派生 align:false] align=False AsyncPerturb=1 n=4603 p=0.5 translate_px=(1,4) rotate_deg=(-1.0,1.0) target=x`，
`ds[0]` 产出形状 `(6,640,640)`，标签未变。

**已验证（训练后）**：clean 0.7262（相对 μ −3.07σ）、4 px 0.6666（+2.24σ vs 基线）、
8 px 0.6095（+7.56σ vs 基线）；8 px 相对衰减由 −29.5% 降到 −16.1%（§13.4 D）。

### 11.9 兜底方案的代价与验收

| 项 | 数值 | 说明 |
|---|---|---|
| 正常态性能 | 不变（0.7637） | S0 与现状完全一致，零额外开销 |

**逐项判读**：

- **A（解绑门控）**：把 CGA 的共享门拆成两路独立 sigmoid 后，理论上应更灵活，
  但实测只在噪声范围内波动（+0.003）。说明**瓶颈不在门控自由度**，而在「两路特征本身已足够互补，
  任何额外门控都是过参数化」。这与 §9.4 融合算子的整体结论一致。
- **B（同步几何增强）**：**−5.48σ 是全项目最显著的负结果**。根因是同步几何变换会让
  RGB 与 IR 的**像素级对应关系被重采样破坏**（双线性插值各自引入误差），
  而模型依赖的正是这种细粒度的空间对应。→ 论文中应作为「为什么不能随便加数据增强」的实证。
  **补充（2026-11-03）**：在 rot15/30 口径上 B 组反而 0.28→0.59、0.09→0.35（§13.4 G），
  所以准确表述是「**牺牲 clean 的像素级对应精度，换取全图几何姿态鲁棒**」——定向交易，不是失效。
- **C（P2）**：+0.005（+0.53σ），**方向正确但不显著**。结合 §13.2 的分桶结果，
  P2 对 <16px 桶有小幅提升，但被大目标桶的波动抵消。
- **D（box/DFL 权重）**：+0.0056（+0.60σ），**不显著**。这是「回归损失占比」假设的直接检验：
  §13.2 提出「<16px 桶框不准 → 调 box/DFL 权重」，实测只涨了噪声级别。
  → **瓶颈不在损失权重的配比**，与 §13.3 「模型 medIoU 已逼近标注抖动天花板」互证：
  再怎么加权回归，也无法突破标注本身的 0.62 px 抖动上限。
- **E（GeoShape 分配）**：−0.0079（−0.84σ），**不显著，方向为负**。
  「分配信号稀释」假设未获支持：换更几何合理的分配度量并没有让 8–16px 目标受益。
  结合 D 一起看，**「改回归/分配」这条路线在 clean 口径上已基本封闭**。
- **F（Async 错位扰动训练）**：clean 口径 **−0.0289（−3.07σ）显著负**——牺牲了干净数据的精度。
  但这是**用 clean 精度换错位鲁棒性**的定向交易，真正的判据是错位区间：
  §13.4 的曲线显示它在 4 px 起反超基线、8 px 反超 **+0.0711**。
  → 结论必须**同时看 clean 掉幅与错位增益**，单看 clean 会得出「无效」的错误结论（见 §13.4 D 节）。

**<16px 桶的深度诊断（本项最关键）**：

| 指标 | 数值 | 含义 |
|---|---|---|
| R@IoU0.5 | **0.837** | 检出能力**不是**瓶颈 |
| IoU ≥ 0.5 的检出占比 | **97%** | 一旦检出，框基本是对的 |
| 中位 IoU（medIoU） | **0.795** | ≈1.0 px 中心偏移 |
| mAP50-95 | **≈0.50** | 但高 IoU 阈值（0.7/0.8/0.9）几乎拿不到分 |
| 标注抖动天花板（P99） | **0.855**（等效 0.62 px） | **模型已逼近数据上限** |

**结论**：
1. **瓶颈不是「找不到目标」，而是「框不够准」**——R50 0.837 说明分类/定位的「有无判断」已做好；
2. 高 IoU 段拿不到分，是因为 <16px 目标只要偏 1 px，IoU 就从 0.8 掉到 0.6；
3. 标注本身的 P99 上限是 0.855，**模型 medIoU 0.795 与天花板只差 0.06** → 继续优化回归的收益空间极小；
4. 因此「提升 mAP50-95」的正确路径不是换融合算子，而是：**提高输入分辨率**（让 16px 目标变成 32px）、
   **改分配策略**（IoU-aware / GeoShape，让正样本匹配更准）、**调 box/DFL 权重**（让回归损失占比更高）。
   → 这三条正是 §12.3 三组实验的依据；**D/E 已实测证伪前两条（回归权重与分配）**；
   F（E10，分辨率）已于 2026-11-03 完成，**增益同样未过 2σ**（重训 +0.19σ、纯推理 +1.09σ，§13.4 K）。
   → 三条候选路径**全部实测完毕，均无显著收益**，这反过来强化了结论三：瓶颈在标注/数据质量，不在模型侧。

### 13.3 标注跨帧抖动天花板

**方法**：不依赖「静止目标」（test 中静止对仅 **19/640**，样本太少），改用**相邻帧同目标 IoU 分位数**：
同一 track 在相邻帧的框应几乎重合，其 IoU 的尾部即标注噪声。

| 桶 | P90 IoU | P95 IoU | P99 IoU | 等效中心偏移 |
|---|---|---|---|---|
| < 16 px | 0.699 | 0.788 | **0.855** | **0.62 px** |
| ≥ 128 px | — | — | **0.980** | 可忽略 |

**结论**：小目标的理论精度上限是 **IoU 0.62~0.65**（不是教科书式的 0.78）。
换句话说，即使模型完美，<16px 桶的 mAP50-95 也不可能超过 0.65 左右。
**这解释了为什么「50-95 只有 0.50」不是模型缺陷，而是数据本身的天花板在 0.5~0.65 之间。**

| `GeoMild` 同步几何增强 | 0.7036 | **0.5906** | **−0.1130** | **0.3491** | **−0.3545** |
| `Async` 单侧错位扰动 | 0.7262 | 0.2705 | −0.4557 | 0.1088 | −0.6174 |

**判读**：
1. **同步几何增强的收益只在旋转口径上显现**：clean 掉 −5.48σ（§13.1 B），
   但 rot15 从 0.28 提到 **0.59**（+2.1×）、rot30 从 0.09 提到 **0.35**（+2.9×），
   衰减幅度由 −48%/−67% 收到 −11%/−35%。**这正是 `eval_robust.sh` 原设计要找的证据。**
   且提升不只是「框回归变准」：mAP50 也从 rot15 的 0.858→**0.962**、rot30 的 0.406→**0.882**，
   **检测本身就没丢**（基线在 30° 时漏检严重，R 仅 0.42）。
2. **噪声尺度**：`concat_s0` vs `concat_s1`（同配置不同种子）在 rot15 差 0.003、rot30 差 0.017。
   因此 Async 相对基线的 −0.012/+0.019 **落在噪声内**，而 Geo 的 +0.31/+0.26 远超噪声。
   → 论文里 B 组不能只写「显著负」，必须写成「**以 clean 精度换取全图几何鲁棒性的定向交易**」。
3. **单侧扰动训练对全图旋转几乎无效**：Async 在 rot15/rot30 上与基线同水平（差异 ≤0.02）。
   原因清楚——训练扰的是**两路之间的相对错位**，而 rot15/30 是**两路同角度旋转**，
   后者破坏的是「目标朝向」，不是「两路对应」。
4. **两类退化必须分开建模**：`Async` 治「配准误差」，`Geo` 治「几何姿态」。
   这解释了为什么没有任何单一模型能同时拿下 clean / 错位 / 旋转三项。
5. **口径提醒**：rot15/30 的 GT 是「旋转后外接框」近似，其绝对数值**不可与 clean 直接比**，
   本表只做**模型间相对比较**（4 个模型共用同一套 GT，偏差同源）。

**I. 图像域无参考配准估计的探索（2026-11-03，结论：本实现下未成功）**

> 目的：把「判据」升级为「方法」，必须有**在线可用的错位量估计**。本节探索最自然的方案——
> 只用 RGB 与 IR 两幅图像、不看注入值，用图像域统计量估出位移。
> **结论：本轮 8 种实现均未达到可用精度（最好 MAE 12.1 px）。**

> ⚠️ **证据强度限制（2026-11-03 复核后追加，必须与本文一起引用）**
> 本节实验存在若干实现与口径缺陷，**不能据此断言「图像配准这条路不可能」**：
> 1. `phaseCorrelate` 返回的位移符号在部分版本里被反解，注入符号是用前 12/15 帧"猜"的，而非用同模态已知变换做单元校验；
> 2. 路由一致率是从「绝对误差 ± err」构造的区间算的，不是真实估计值；
> 3. native 空间的 warp 与 letterbox 后的 warp **并非严格等价**；
> 4. NMI 只检查了前 8 帧，且来自同一序列，样本不足；
> 5. 未做边缘掩膜外的视差补偿，也未尝试 ECC / 特征点 / 学习式配准。
> 因此本节只应表述为「**本轮 8 种强度域/边缘域实现在本数据上未达可用精度**」，
> 不能表述为「图像域配准在本数据上不成立」。真正的结论应来自 J 节的模型侧对照实验。

真值取 `eval_split --ir-shift` 的注入量（640 输入空间像素），估计在原生分辨率做完再按 letterbox
比例换算回 640 空间；共 614 帧 × 6 档。

1. **NCC 暴力扫描（±24 px）**：6 帧中有 4 帧的相似度峰跑到扫描边界（−24 或 +24），
   且峰随位移单调漂移 —— 这是**全局亮度布局**（天空/地面明暗梯度）造成的伪峰，不是配准峰。
2. **归一化互信息（NMI）网格搜索（±12 px，32 bin）**：8 帧中只有 **2 帧**的峰能跟随注入位移
   （01016：0→+1、8→−7；01033：0→0、8→−8），其余 6 帧峰固定在边界；
   峰值相对背景仅 **+0.69~+1.77σ**，没有可分辨的主峰。
3. 上述现象说明：**在本轮实现与参数下**，RGB 与 IR 之间没有被这些强度/边缘统计量恢复出的稳定主峰。
   但这是「实现与参数层面未成功」，**不等于证明像素级对应不存在**（见上方证据强度限制）。

- **次线性**：注入 8 px（原生约 7.3 px）时，估计相对 clean 只上升约 **4.1 px**（约 0.55×）。
- **订正（2026-11-04）**：此前把该次线性归因于「IoU 门限滤掉了大位移配对」，**该归因已被证伪**。
  改用距离门限（`d ≤ 0.75·sqrt(area)`，在本数据上对 7 px 位移完全不构成过滤）后，
  估计值为 3.20 → 7.24，**漂移仍是 4.04 px**，与 IoU≥0.1 的 4.10 px 几乎相同。
  → 次线性来自模型侧（两个头的框中心并不随图像内容 1:1 移动），**具体机理尚未确定**，
  不得再写成「门限造成的匹配偏差」。也正因如此，**α 映射必须靠实测标定，不能用几何换算**。
- 特异性对照：只注入水平位移，`dy` 全程稳定在 1.4~1.5 px，竖直方向无响应。

**J-5　必须写进论文的限制**

1. **成本翻倍**：路由要同时跑基线 + Async 两个网络。按板端 int8 单模 64 ms 计，约 **128 ms/帧**，
   12.7 FPS 会降到 ~7.8 FPS。**「零额外算力」的表述已作废。**
2. **估计饱和**：对 ≥6 px 的严重错位会低估，因此 L6/L8 拿不到 Async 全额增益（缺口 0.009~0.012）。
3. **覆盖率 85%**：约 15% 的帧无有效框对，回退为基线预测。
4. **只验证了纯平移**，且注入时 GT 不动；旋转/尺度型错位未验证。
5. **两模型路由 ≠ 单模型内部路由**：真正的「错位感知自适应融合」应在**一个网络内部**
   按估计量调节融合权重，那才是方法型贡献；当前实现只是工程上的双模型调度。
   **（2026-11-04 订正：单模型内路由已按 M-2 判为不可行——错位量在特征域不可分，α 只能学成常数。
   故这条不再是待办，而是已被否决的设想；方法型贡献改由数据侧增广 + 推理侧路由承担。）**
6. 离线 AP 与验证器有 ±0.006 的实现偏差。

**K. E10：输入分辨率 800 实验（2026-11-03 完成）**

> 训练：`mdp150_M0Img800_s0`，imgsz 800、batch 8、seed 0、150 ep（**跑满，无早停**，
> best 在 ep148）、AMP false。GPU 04:00 起跑，13:21 结束。
> 复评：`eval_split.py --imgsz 800`，mendeley test 全量 614 帧。

*表 K-1　分辨率消融（4 组，均为 test 全量、dual 标签、fuse 头 mAP50-95）*

| # | 训练分辨率 | 推理分辨率 | batch | fuse mAP50-95 | 相对基线 | 判读 |
|---|---|---:|---:|---:|---:|---|
| 1 | 640 | 640 | 32 | **0.7637** | — | 基线（`concat_s0`） |
| 2 | 640 | **800** | 8 | **0.7739** | **+0.0102（+1.09σ）** | **只改推理分辨率**，不重训 |
| 3 | **800** | **800** | 8 | 0.7655 | +0.0018（+0.19σ） | E10 正式配置 |
| 4 | 800 | 640 | 8 | 0.7551 | −0.0086（−0.91σ） | 反向对照 |

**核心发现（三条，都可直接进论文）**

1. **E10 这一路（重训 800）没有拿到分辨率的收益。** 0.7655 相对基线 +0.0018，仅 0.19σ，
   远低于 2σ=0.0188 判据；val 口径也同样持平（基线 0.7743 vs Img800 0.7734）。
   两个口径同时持平，说明**不是 test 抽样噪声**。
2. **分辨率本身确实有用，但收益来自「推理分辨率」而非「重新训练」。**
   基线权重不改、只把推理尺寸提到 800 就得到 **0.7739（+1.09σ）**，
   **比重训出来的 800 模型还高 0.0084**。→ 「花 150 epoch 重训高分辨率模型」在本数据上是**负收益**，
   正确做法是**固定权重、提高推理分辨率**（或用高分辨率做微调而非从头训）。
3. **反向对照证明这个 800 模型整体偏弱**：它在 640 推理时只有 0.7551（低于基线 0.7637，−0.91σ），
   说明 `batch 8` 这一混杂因素确实拉低了模型本身的质量。

**混杂与限制（必须同时写明）**

- **batch 8 vs 32 不可忽略**：Img800 因显存限制用 batch 8，基线用 32。第 4 组（800 训练 / 640 推理）
  显示该模型在同等 640 口径下就低 0.0086，因此第 1↔3 组的对比**不能干净归因于分辨率**。
  真正可比的是第 1↔2 组（同权重、同 batch 口径无关，只改推理尺寸）。
- **单种子**：σ=0.0094 来自三种子基线，未为新配置重估。
- **0.7739 仍在 2σ 内**（+1.09σ），只能表述为「方向正向、未达显著」，
  不能写成「分辨率提升带来显著增益」。
- **未测端侧延迟**：800 面积是 640 的 1.5625 倍，按板端 int8 单帧 64.06 ms 线性外推约 **100 ms**
  （15.6 → ~10 FPS）。**这是估算，未实测**；若要在论文里写延迟，必须在板端重测。
- 第 2 组（基线@800）对训练分辨率而言是分布外推理，其正向结果也可能来自
  「test 图像原生分辨率 587×450 / 579×437 等，800 letterbox 的缩放比更接近 1」这一效应，
  即**减少了上采样损失**，而非「模型变强」。论文中应把这一点作为机理解释给出，并注明未单独验证。

**结论**：分辨率这条杠杆**没有通过显著性检验**（+0.19σ 重训 / +1.09σ 纯推理），
且代价明确（面积 ×1.56、端侧延迟约 +56%）。
→ 论文应写成「分辨率是唯一尚未被否证的精度杠杆，但本数据上其增益处于噪声量级；
    且增益主要来自推理尺度匹配，而非模型容量/表征」。
这比「提升分辨率能涨点」更诚实，也更有信息量。

**L. 错位感知门控融合：可行性消融与闭环尝试（2026-11-04 新增）**

> 背景：小论文改为**方法型**选题，方向定为「单模型内的错位感知门控融合」——
> **本节记录的是该方向的可行性与失败点；该方向已由 §13.4 M-2 判为 NO-GO，本节保留作为过程记录。**
> 在融合节点按在线错位量调节 IR 支路贡献，替代上一节 J-4 的**双模型硬切换**（后者需 2× 算力）。
> 本节记录两件事：**门控到底有没有收益空间**（结论：有），以及**能否用推理时逐帧切换来验证**（结论：不能）。

**L-1　为什么不先训网络：先做"有没有空间"的判定**

融合节点是 `Concat(RGB, IR) → 1×1 Conv`，IR 固定在拼接的**后一半**。因此只要在拼接后
把后一半乘一个标量 α，就等价于"调节对 IR 的信任度"，**不需要重训、不需要改结构**。
α=1.0 即原模型，α=0 即完全不用 IR。

> 说明：不能用「固定 α vs 学习 α」做消融。当 α 是常数时，它会被紧邻的 1×1 卷积权重
> **完全吸收**，与基线在函数上等价，必然跑出"无差异"的假结论。

**L-2　α 扫描（整档统一 α，验证器口径，GPU）**

*表 L-1　fuse mAP50-95（614 帧 test，IR 水平位移）*

| α | 0 px | 2 px | 4 px | 8 px |
|---|---:|---:|---:|---:|
| 1.0 | **0.7631** | 0.7182 | 0.6455 | 0.5384 |
| 0.8 | 0.7535 | **0.7262** | 0.6716 | 0.5871 |
| 0.6 | 0.7182 | 0.7033 | **0.6732** | 0.6134 |
| 0.4 | 0.6558 | 0.6512 | 0.6455 | **0.6160** |
| 0.2 | 0.6121 | 0.6100 | 0.6089 | 0.6014 |
| 0.0 | 0.5388 | 0.5388 | 0.5388 | 0.5388 |

**最优 α 随错位严格单调下降：1.0 → 0.8 → 0.6 → 0.4**，收益 **0 / +0.008 / +0.028 / +0.078**。
四档 oracle 均值 **0.6946**，常基线 0.6663（+0.028）。

两个交叉验证：
1. α=0 四档恒为 **0.5388**，而基线 8 px 为 0.5384 —— 独立复现了「8 px 时融合已不如纯 RGB」。
2. 离线复算管线（±0.006 偏差）给出同一结构：oracle α = 1.0/0.8/0.7/0.5，均值 0.6939 vs 基线 0.6670，
   **两条独立管线结论一致**。

**L-3　闭环尝试：用在线估计逐帧选 α（失败）**

用 J-3 的中心位移做因果窗中位数，按「留一档」拟合 α(s)（在 3 个档位上拟合线性映射，预测留出档），
逐帧选最近的 α 网格值，再合并预测重算 AP：

| 窗口 W | L0 | L2 | L4 | L8 | 均值 |
|---|---:|---:|---:|---:|---:|
| 5 | 0.7299 | 0.6974 | 0.6450 | 0.5153 | 0.6469 |
| 10 | 0.7391 | 0.7067 | 0.6470 | 0.5121 | 0.6512 |
| 20 | 0.7393 | 0.7097 | 0.6475 | 0.5109 | 0.6519 |
| 常基线 | 0.7580 | 0.7189 | 0.6499 | 0.5414 | **0.6670** |

**闭环全面低于基线**（最好 0.6519，−0.015），尤其 8 px 档从 0.5415 掉到 0.5109，
而该档的整档 oracle α 明明是 0.6163。

**L-4　失败归因：不是估计量不够准，而是"逐帧混用不同 α"本身破坏了池化 AP**

混合对照（不涉及任何估计量，纯粹人为按帧交替指定 α）：

| 档 | 全部 α=1.0 | 全部 α=0.5 | 50/50 交替 |
|---|---:|---:|---:|
| 4 px | 0.6499 | 0.6593 | **0.6433** |
| 8 px | 0.5415 | **0.6163** | **0.5581** |

8 px 时「一半好、一半差」的混合结果（0.5581）**低于两种纯方案中的任何一种**。
原因是置信度标定发生了系统性偏移：

*表 L-2　8 px 下各 α 的置信度分布*

| α | 框数 | 均值得分 | 帧内最高分均值 | ≥0.25 框数 |
|---|---:|---:|---:|---:|
| 1.0 | 1062 | 0.4416 | **0.7113** | 577 |
| 0.5 | 853 | 0.3758 | **0.5086** | 431 |
| 0.2 | 598 | 0.2740 | 0.2645 | 217 |

同一帧在 α=0.5 下的框**分数整体更低**。而 mAP 是把**全部帧的框放在一起按分数排序**计算的，
于是被衰减帧里"更好但分数更低"的框排在被保留帧"更差但分数更高"的框之后，
召回曲线在低精度区才补上 → 池化 AP 反而下降。

→ **这是一个评测口径问题，不等于"门控在部署中无效"。**
但它确实说明：**推理时逐帧切换 α 无法用池化 AP 验证**，也就不能作为方法有效性的证据。

**L-5　本节结论与对选题的影响**

1. **门控的收益空间是真实且清晰的**：整档 oracle α 在两条独立管线上都给出 +0.027~0.028，
   且最优 α 随错位单调下降、8 px 档收益最大（+0.078）。**方法方向成立。**
2. **"推理时逐帧切换"这条验证路径不成立**，原因已在 L-4 定位并量化，不是估计精度问题。
3. 因此下一步**必须改为联合训练门控**：把 α 作为网络内部的连续量（由该帧的特征/估计量产生），
   端到端训练。这样所有帧共用同一套置信度标定，池化 AP 才是有效指标，
   同时顺带解决「测试时衰减属于分布外推理」的问题。
4. 与 §13.4 J-4 的关系：双模型硬切换（+0.0148，2× 算力）与门控（oracle 上界 +0.028，1× 算力）
   不是同一量级的目标；门控的上界更高且更省，但**需要训练**。

**订正（2026-11-04）**：第 3、4 条的前提已被 §13.4 M-2 证伪——错位量在置信度、融合颈、浅层特征
三层上均不可分（AUC≈0.50），门控只能学到常数 α，而常数会被融合处的 1×1 卷积吸收、与基线等价。
故「联合训练门控」不再是下一步，L 的 oracle 上界（+0.028）转为「知道真值时的不可达上界」。
方法出路改到数据侧（单侧增广）与推理侧（双模型路由），即选题四。

**必须写明的限制**：α 只在融合拼接处**统一**作用于 P3/P4/P5；只验证了水平平移；
oracle α 由 GT 档位挑选，是上界不是可达性能；L-3 的 α 映射是在本测试集的 3 个档位上拟合的，
虽为留一档预测，仍属同集标定。

**M. 两条 NO-GO：频段诊断闸门与单模型内错位门控（2026-11-04 新增）**

> 本节记录两件被证伪的方案。二者都不是"做不出来"，而是**前置条件不成立**：
> 前者是选题二的立题前提（频段间存在模态对立），后者是选题一"单网络内部门控"的可行性前提（错位量可从特征读出）。

**M-1　选题二频段诊断闸门：NO-GO**

判据操作化为四条，避免原先"能量比与局部信噪比"并列、无法判定的问题：

1. 频带：DoG 三带，σ 以原生像素计——B1 = G(1)−G(2)、B2 = G(2)−G(4)、B3 = G(4)−G(8)；不在网络特征图上取，避免与训练状态耦合。
2. 可靠性：目标区对背景环的对比度信噪比 `CNR = |μ_t − μ_r| / (σ_t + σ_r)`，背景环取目标框 1.8 倍外接矩形减目标区；两模态都按灰度计算。
3. 显著性：按 sequence 聚类 bootstrap 2000 次、95% 分位区间；判据看 `Δ = CNR_rgb − CNR_ir` 是否跨 0。
4. 样本底线：单格有效框 <30 或序列 <8 不出结论；最短边 <8 px 不参与。

**证据强度限制（必须写进论文）**：
- CNR 只度量局部对比度，不含"检测器 × 频段"的联合口径；AP 复核覆盖了尺度维度，但 **AP 本身没有频段维度**，两者只能合起来支持"无反转"，不能单独支持"某个频带上谁更强"；
- AP 复核的配对 bootstrap 区间**全部跨 0**（51 序列 / 552 GT 的外部效度限制），因此只能说"未出现反转"，**不能**表述为"红外显著优于可见光"；
- 若审稿人要求频段级的检测器证据，需要在 DoG 滤波后的图像上推理，但模型未在该分布上训练，结论不可解释，故未做。

`…/gate_head_ap.py`（输出 `gate_band/gate_head_ap.json`）。

**M-2　单模型内错位门控：NO-GO**

在三个层级上检验"错位量能否从模型内部读出"：

| 层级 | 检验对象 | 结果 | 可用性 |
|---|---|---|---|
| 逐帧置信度 | 最高分、`conf_ir/conf_rgb`、`−conf_fuse` | AUC 0.496~0.528 | 随机 |
| 融合颈深层特征 | 五类描述子（池化/余弦/差） | AUC 0.47~0.59 | 随机 |
| stride 2/4/8 浅层特征对 | NCC、峰值滞后 | NCC AUC 0.472~0.569；唯一"亮点" `peak_lag_x=0.718` 经对称性检验被否（+8 时 1.34 cell、−8 时 0.84 cell，中位数恒 0，峰相关≈0.03） | 随机 |

**判定：** 错位量不进入任何可池化统计量 → 逐帧门控的输入不含可分信息；α 只能收敛为常数，而常数权重会被融合处的 1×1 卷积吸收，与基线等价。因此**单网络内的错位感知门控判为 NO-GO，不启动长训练**。

与 §13.4 L 的关系：L 的 α 扫描上界（oracle +0.028）仍然成立，但它需要"知道每帧的错位量"才可达；L-5 第 3 条"必须改为联合训练门控"据此**作废**——门控输入没有信息，联合训练只会学到常数。方法出路仍在数据侧（单侧增广）与推理侧（双模型路由）。

限制：本检验覆盖置信度、neck、浅层特征三层，**未覆盖"可学习配准子网"这一路**；该路线属需要训练的额外模块，不在此零训练检验的范围内，未做。

**M-3　对选题的影响**

- 小论文主线固定为**选题四**：单侧扰动增广 + 留出标定路由（证据：交叉点 2~4 px、纯真实 8 px 衰减 −0.276→−0.136、留出命中 0.967、六档均值 +0.0148~+0.0236）。
- 大论文创新点由四条降为三条：错位增广与路由、合成域伪特征诊断与 IPW 分层采样、外观—运动双证据开放集判别。
- 两条 NO-GO 写入第四章"难点发现"：**难点二（错位在模型内部不可观测）**、**难点三（频段维度无可学习对立面）**，作为方法选型的依据，而非创新点。

### 13.7 结论分析

**结论一：融合算子的复杂度收益已到边界。**
6 个融合算子全部不显著或显著为负，A（解绑门控）+0.32σ、C（P2）+0.53σ 也都在噪声内。
**「朴素 Concat + 1×1 Conv」就是本数据上的最优解**，更多参数/门控只会过拟合 51 个序列。
→ 论文的核心论点应是「**验证了融合复杂度的边际收益边界**」，而不是「提出了更好的融合算子」。

**结论二：融合增益真实，且 IR 主导。**
去 IR −0.2775 > 去 RGB −0.1896，且置黑与置灰降幅接近（差 0.008），
说明增益来自**信息互补**而非分布外伪影。这是本项目**最硬的正向证据**。

**结论三：精度瓶颈在「框的精度」，不在「找不找得到」。**
<16px 桶 R50 0.837、IoU≥0.5 占 97%，但 mAP50-95 只有 0.50。
根因是标注本身抖动（P99 等效 0.62 px），模型 medIoU 0.795 已逼近天花板。
→ **继续在融合层面优化是错方向**；「标签分配」「回归损失权重」「输入分辨率」三条现已**全部实测**
（D/E 证伪前两条；E10 的分辨率增益 +0.19σ / +1.09σ 均未过 2σ，见 §13.4 K）。
即：**在现有数据与标注质量下，不存在还能拿到显著精度的单点杠杆**，
这本身就是本课题的验证性结论之一。

**结论四：真实部署的最大障碍是「对齐」，不是「算力」。**
错位 1 px 掉 1.8σ、2 px 掉 4.8σ、6 px 时融合已不如单模态。
而 RK3588 端侧算力**完全够用**（int8 15.6 FPS、整链 12.7 FPS、300 帧零丢帧）。
→ 论文第 5 章应把「对齐敏感性」作为**核心发现之一**，并给出「训练侧扰动 + 工程侧门控」的双重兜底。

**结论五：「改回归权重 / 改标签分配」这条路在 clean 口径上已封闭；错位鲁棒只能靠定向交易。**
D（box/DFL 权重）+0.60σ、E（GeoShape 分配）−0.84σ，两项均在噪声内 —— 与 §13.3 的标注抖动天花板互证：
回归与分配层面已无可见增益空间。F（Async 错位扰动）是唯一改变曲线形状的干预，
但它**以 clean 精度换错位鲁棒**：clean −3.07σ（不满足进主线判据），4 px 起反超、8 px **+7.56σ**。
→ 正确的用法不是「替换基线」，而是**按错位量路由**（clean / ≤1.5 px 走基线、≥2 px 走 Async），
这与 §11 的兜底门控互补，构成比「切单模态」更优的中间档。
**该方案已由 2026-11-03 的两项补充实验量化**：增益跨方向成立（竖向 4 px +8.11σ、旋转 2° +8.23σ），
路由 oracle 六档均值 **0.6901**，比常基线高 **+0.0236**；切换阈值收紧到 **1.5 px**（§13.4 E/F）。

**结论六：「配准误差」与「几何姿态」是两类互不相同的退化，必须用不同手段治。**
- 训练期**单侧扰动**（`Async`）治的是「两路之间不对应」：对水平/竖向/旋转错位全线有效（4 px 起 +8~14σ），
  但对**全图同角度旋转**（rot15/30）几乎无效（与基线持平）。
- 训练期**同步几何增强**（`Geo`）治的是「目标朝向」：clean 掉 −5.48σ，但 rot15 0.28→**0.59**、rot30 0.09→**0.35**。
→ 因此**不存在单一模型同时拿下 clean / 错位 / 旋转**。论文应把这一点写成方法论建议：
先判退化来源（标定残差 or 姿态差异），再选对应训练策略，而不是统一加数据增强。

**结论七：端侧链路已闭环，但只到「文件回放」。**
从 GPU 权重到板端 NPU 出框、跟踪、告警、证据帧，全链已实测跑通；
真机 V4L2 接入差 6 项改动（MPLANE 为必做），**硬件到位即可续做**。

**结论八：错位判据通过了留出验证，但其证据强度必须靠「决策级」而非「曲线形状」来体现。**

按 sequence 5 折留出，用 4 折拟合临界点（4 px）后在留出折上逐档选模型，命中 **29/30 = 0.967**
（对照：常基线 0.467、随机 0.500），五折的逐档胜者方向完全一致（0~1 px 基线全胜、4~8 px Async 全胜）。
但同一批数据上的「曲线形状方向一致率」五折 Spearman 全为 **1.000**——这是**饱和指标**，没有区分力，
因为每一折的衰减曲线本身就单调。→ 论文必须以 **0.967 的决策命中率**为主结果，形状检验只作辅助，
否则会被审稿人直接指为「把消融写成了判据」。
另需注意：真实域 8 px 掉 **0.276**、合成域仅掉 **0.106**，全量曲线被 19.2% 合成帧**系统性稀释**，
主表须同时给「全量」与「纯真实」两列（§13.4 H）。

**结论九：在线失效信号要从模型里取，但「取哪个量」必须逐帧验证，不能想当然。**

第一阶段（图像域）：四种强度/边缘域估计器（灰度／梯度／Canny 相位相关 + NCC/NMI 扫描）未达可用精度，
最好一组 MAE 仍 **12.1 px**。但该轮实验存在符号反解、样本不足（8 帧同序列）等实现缺陷，
**只能表述为「本轮实现未成功」，不能断言图像配准在本数据上不成立**（§13.4 I 的证据强度限制）。

第二阶段（模型侧，决定性）：把 6 档 × 614 帧 × 4 头全部逐帧导出后逐一检验——
- **最高置信度 / `conf_ir÷conf_rgb`：AUC 0.496~0.528，留出分类平衡准确率 0.49~0.52 → 等于随机，不可用**；
- **框一致性（F1、匹配 IoU）：趋势清楚但 AUC 仅 0.55 → 只能作辅助**；
- **两头框中心位移：AUC 0.83，因果窗平滑后 1.00，估计误差 <1 px → 可用，但对 ≥6 px 会饱和**。

用该估计量做真实合并路由，六档均值 **0.6819**，比常基线 +0.0148、比常 Async +0.0085，
拿到 oracle 增益的 **72%**，且 clean 档几乎不退化（§13.4 J-4）。

代价必须同时写明：**路由需要同时运行两个模型，约 2× 算力**，
「零额外算力」的说法已作废。且当前只是双模型调度，**不是单网络内部的错位感知融合**。

**2026-11-04 补**：单网络内部的错位门控已按 §13.4 M-2 检验并判为**不可行**（置信度、融合颈、浅层特征
三层 AUC≈0.50，错位量不进入任何可池化统计量），因此这句不是「尚未实现」，而是「已验证在零训练口径下不可实现」。
方法主线据此定在数据侧增广与推理侧路由。

**对论文的净收益**：
本轮的负结果（B −5.48σ、6 算子不显著）与错位曲线，构成了一个**比正结果更有说服力的叙事**：
「双光谱融合在理想对齐下有效，但在真实标定误差下会迅速失效 —— 这正是本课题的验证性贡献」。

### 14.3 线程模型：为什么推理必须离开主线程

首版把「取帧 → 推理 → 上屏」放在主线程串行，实测**上屏只有 5.8 FPS**（源 10 fps），
画面明显一顿一顿。原因是 RKNN 单帧 66 ms 是硬下限，主线程被它占住，解码线程产出的帧
只能在槽里等（`takeLatest` 只保留最新一帧，其它全丢）。

现在的分工：

```
解码线程(VideoSource) ──最新帧槽──▶ 主线程 QTimer(10 ms)
                                      ├─ 立即上屏（源帧率，画面不卡）
                                      └─ 空闲才投递 1 帧 ──QueuedConnection──▶ InferenceWorker 线程
                                                                                  └─ 结果回主线程 → 叠框/指标/告警
```

三条约束：

1. **单帧在途**：`m_busy` 为真时不再投递，处理不过来就自动丢帧，**延迟不累积**；
2. **叠加层沿用**：两帧之间沿用上一次的检测框/轨迹（`m_lastDets/m_lastTracks`），画面不闪；
3. **`Kernel` 互斥**：`QMutex` 保护，工作线程推理与主线程「改阈值/换源/重置跟踪器」互斥。

效果：上屏 5.8 → **9.9~10.0 FPS**（与源帧率对齐），处理帧率仍 5.1~5.3 FPS，
延迟中位数 165 → **118~124 ms**。

同时修掉的三个统计/显示缺陷：

| 缺陷 | 根因 | 修法 |
|---|---|---|
| mAP50 恒 0、P/R 0 | `publish()` 先发帧再 `m_seq++`，首帧序号为 1，与 0 起算的 GT 键整体错位一帧 | `m_seq` 初值 `-1`，首帧发布后为 0 |
| 帧率越跑越低 | 累计平均把启动阶段摊入 | 近 30 帧**滑动窗口**帧率 + 上屏帧率单独统计 |
| 延迟虚高 | 累计平均含首帧模型预热 | 面板显示 **600 帧滑动中位数**（P95 保留） |

### 14.4 指标口径（论文/报告引用时必须写明）

| 指标 | 定义 |
|---|---|
| 告警延迟 | 帧被取出处理 → 出结果（预处理 + NPU + 跟踪）的墙钟差；面板显示 600 帧中位数 |
| 处理帧率 | 近 30 帧「出结果」时刻的平均间隔倒数（不含被丢弃的帧） |
| 显示帧率 | 近 1 s 实际上屏帧数；与源帧率对比即可判断是否卡顿 |
| 检测准确率 | 逐帧 IoU≥0.5 贪心匹配（按置信度降序）+ 全局累计 11 点插值 AP50；**只统计有标注的帧**。统计区间随播放时长扩大，短跑与全片数字不可直接比较（§14.5.1） |
| 目标数量 | 当前帧已确认轨迹数 |
| NPU 推理 | `rknn_run` 纯推理；单帧总耗时 = 预处理 + NPU + 跟踪 |

无标注视频（如 `demo_eo.mp4`）不计算 mAP，指标卡显示 `—`，避免用阈值法伪标注得到 0 分误导。
