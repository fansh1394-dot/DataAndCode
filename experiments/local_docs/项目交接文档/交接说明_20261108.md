## 3. RK3588 端侧复测（CNW）

链路：`export_onnx_raw.py` → `convert_rknn.py`（rk3588 / int8 / normal / channel / calib160）→ `rk_probe_e2e.c` → `e2e_ref.py` → `e2e_cmp.py`。

| 模型 | 板端 AP50 | P | R | meanIoU | 框数 | LAT (ms) | E2E (ms) |
|---|---|---|---|---|---|---|---|
| CNW int8 | **0.9604** | 0.9722 | 0.9722 | 0.8037 | 36 | 75.28 / 74.49 | 98.65 / 97.04 |
| 基线 int8 | 0.8899 | 0.8684 | 0.9167 | 0.8052 | 38 | 76.00 / 74.65 | 99.20 / 98.02 |

- ONNX 结构与基线完全一致（1092 节点 / 19 op types / 输出 (1,5,80,80)(1,5,40,40)(1,5,20,20)）；rknn 体积差 +128 B。

- 基线板端数字与 2026-11-01 记录的 `normal160` 完全一致 → 链路可复现。
- 时延与历史 64.06 / 78.57 ms 差约 11 ms，属当日测量/构建漂移，**不能归因于模型**。
- 无框帧（thr 0.25）：CNW `33040/34145/42108/42243`；基线多一个 `01002`。

## 5. DT800 跨分辨率特征蒸馏（E11）

### 5.1 训练协议

- 150 ep、imgsz 640、seed 0、amp false、lr0 0.01、box 7.5 / cls 0.5 / dfl 1.5、mosaic 1.0、close_mosaic 15。
- **batch 16（协议偏差）**：显存不足，基线为 32；必须在论文/结论中标注，不能与基线直接等价比较。
- 教师 `s0` imgsz=800 前向，学生 640；层 48/51/54，`F.interpolate` 对齐；纯特征 KD，四头 dict 输出用全图均匀掩码，chunk=8。
- 蒸馏项确实生效：末轮 `d_feat 3.86`、`cwd 7.45`；末轮 val fuse mAP50-95 0.7744。

### 5.2 test 分桶（fuse 头，552 GT）

- AP50 基本持平（0.9292 vs 0.9270），AP75 大幅上升 → 收益集中在高 IoU 端，检出率不是瓶颈。

### 5.3 判定（§6.1）

| 条件 | 值 | 判定 |
|---|---|---|
| lt16 AP50-95 ≥ 0.565 | 0.5544（+1.06σ） | **未达**（差 0.0106） |

| 整体 mAP50-95 ≥ 0.7449 | 0.7765（+1.36σ） | 通过 |

→ **2/3，不满足「三项全过」，不保留**。专项指标合格：R@0.25 0.8961 ≥ 基线最低 0.8896；无 GT 帧 FP/frame 0.0000（0/66）。

## 6. 下一步实验（按优先级）

### P0 · E19：800 裁切训练（640 推理）——主线

**依据链**：
1. E08（640 训练 + 800 推理）是唯一达线结果：lt16 0.5731（+2.6σ）。
2. E09（800 重训 + 800 推理）失败 0.5479 → 单纯上采样训练无效，增益来自**输入网格密度**。
3. E11（800 教师 → 640 学生）0.5544 未达线，但 AP75 +0.060 → 蒸馏只能部分迁移定位信息。
4. 因此唯一未试且可能在 640 推理下复制该增益的，是**训练期提高目标在输入网格中的像素占比**，即裁切放大。

**设计**：
- 随机裁切原图（约 590×460）：边长取 0.6–0.85、必须包含 GT，再 letterbox 到 640；裁切概率 ≈0.6，其余帧保留全图；mosaic 保留。
- 等效放大 1.2–1.7×，对齐 800 推理的 1.35×。
- 协议：150 ep、batch 32（若显存允许）、seed 0、amp false，其余同基线；先 2 ep 冒烟。
- 评估同口径：`bucket_ap.py` + `temporal_consistency.py` + ultralytics test。
- 判定线：lt16 ≥0.565 / AP75 ≥0.582 / 整体 ≥0.7449。

**风险**：裁切改变上下文与尺度分布，可能伤 gt64 与整体；需同时看 b32_64/gt64 桶。

### P1 · E23：RK3588 int8 @800 实测——并行，不占 GPU

- 目的：把唯一正向结果（E08）落到部署口径，决定论文是否走「800 推理 + 时延权衡」主线。
- 链路复用 CNW 复测：`export_onnx_raw.py`(imgsz=800) → `convert_rknn.py` → `rk_probe_e2e.c` → `e2e_cmp.py`。
- 判定线：E2E ≤120 ms，且与 ORT@800 的 top1/AP50 偏差 <2%。
- 历史估计：640 为 ~75 ms，800 预计 ~115–120 ms（8–9 FPS），需实测确认。

### P2 · E24：DT800 batch 32 修正复跑——仅作保险

- 目的：排除 batch 16 协议偏差；需 GPU 连续空闲 ≥20 GB。优先级低于 E19。

### 不建议现在做

- 鸟机判别（E12/E22）：当前数据集无鸟标注；3rd_Anti-UAV 也只有 `uav` 单类。
- 3rd_Anti-UAV 入训：单模态 IR，破坏双光谱输入定义。
- 频域路线（A1–A3）：§7 诊断已触发终止条件（lt16 在 P3 仅 1.49 单元）。
