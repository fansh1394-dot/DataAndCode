# 鸟机判别实验方案（E26–E34）

> 版本：2026-11-10（北京时间）
> 定位：把交接文档中「⛔ 阻塞」的鸟机判别（E12/E22）拆成可执行、可验收的完整实验链，覆盖**数据 → 训练 → 量化 → RK3588 端侧 → 实时视频流 → 复杂场景**全链路。
> 口径继承：只用 test 出结论；val 只用于早停/选阈值；不把种子噪声写成增益；板端只写 `/tmp`；服务器代码为唯一权威版本。
> 本文所有「预估」均显式标注，未实测的数字不写成结论。

---

## 0. 关键决策（先看这一节）

### 0.1 部署态是二态，不是三态

台账「鸟机判别」sheet 原设计为 `鸟 / 无人机 / 不确定` 三态。本方案**在部署链路上强制二态**：

- 输出只有 `drone` 与 `bird`，由 argmax 决定；
- `drone` → 画框 + 标注 `drone` + 触发告警；
- `bird` → 画框 + 标注 `bird` + **绝不告警**；
- 「不确定」只保留为**离线分析量**（置信度、abstain 曲线、ECE），不进入告警判定，否则无法满足「告警准确率 100%、无误告警」的验收要求。

三态作为论文中的风险—覆盖率分析保留，不作为系统行为。

### 0.2 主线：R2 二类检测器；R1 级联作为低成本备选

已确认：终端为双光谱相机，且**允许改动已验收的 UAV 检测器**。因此主线改为 **R2（nc=2 单阶段）**：

```
双光谱帧 → M1' nc=2 检测器（warm start，0=bird、1=drone）
          → M3 时序投票 + 告警状态机
          → UI / alerts.jsonl
```

理由：

1. 单次前向同时输出框与类别，端侧流水线最短，告警逻辑最简单；
2. AVID 已提供 32 040 对双光谱鸟/机样本，可直接支撑二类训练；
3. 已获准改动检测器，UAV 回退风险用护栏控制（lt16 掉点 ≤1 pp、整体 ≥0.7449）。

**R1 级联**（nc=1 检测器 + 6 通道 crop 分类器）保留为：

- 低成本备选：若 R2 的 UAV 护栏失败或鸟类 AP 不达标，回退 R1；
- 论文消融：回答「单阶段 vs 级联」的路线选择问题。

**D0** 不再作为路线门禁，而是零成本诊断：测现有 nc=1 检测器对鸟的提议召回，用于判断 R1 是否仍可作为备选，并为论文提供基线。

### 0.3 端侧工作点

| 档位 | 检测输入 | 用途 | 时延（实测/预估） |
|---|---|---|---|
| 实时档 | 640 int8 | 鸟机判别**验收档**，加判别器后仍 ≤120 ms | 检测 95.36 ms（实测）+ crop/判别 6–10 ms（预估）+ 跟踪/上屏 4–6 ms → **约 105–112 ms** |
| 精度档 | 736 int8 | 仅无人机模式 / 离线高精度，判别器隔帧跑 | 115.05 ms（实测）+ 6–10 ms → 约 121–125 ms |

验收一律以 **640 实时档** 为准；736 档只作为精度上界与对比，不用于「≤120 ms」的判定。

## 1. 任务定义与验收口径

### 1.1 类别与标签

| id | 名称 | 定义 | 告警 |
|---|---|---|---|
| 0 | `drone` | 旋翼/固定翼无人机，含悬停、机动、远距小目标 | 是 |
| 1 | `bird` | 飞鸟（鸽、燕、鸥、猛禽等），含滑翔、扑翼、群飞 | 否 |
| — | `ignore` | 遮挡 >70%、无法判别、地面车辆/人物/风筝/飞机等 | 不参与分类统计，不告警 |

标签规范：

- 框贴紧目标外接矩形，不含旋翼虚影拖尾；运动模糊帧按可见主体标注。
- 等效边长 <8 px 的目标标 `ignore`，不进入 95% 统计。
- 鸟群按单只标注，无法分离的整团标 `ignore` 并记录。
- 双人复核：随机抽 10% 复核，类别一致率须 ≥98%，否则整批返工。

### 1.2 指标定义

**分类指标（轨迹级为主，帧级为辅）**

- 帧级：对与 GT IoU≥0.5 的匹配框统计混淆矩阵、per-class recall/precision、macro-F1。
- 轨迹级：一条轨迹取 T=5 帧投票后的类别，统计 per-class recall 与 macro-F1。**95% 以轨迹级为准**，帧级同时报告。
- 置信区间：按**序列聚类 bootstrap**（不是按帧独立），报告 95% Wilson/percentile CI。

**告警指标（事件级）**

- 告警 TP：对 GT 为 drone 的轨迹触发了告警；
- 告警 FP：对 GT 为 bird 或背景的轨迹触发告警；
- 告警 FN：GT 为 drone 的轨迹从未告警；
- 告警准确率 = TP / (TP + FP)；漏告警率 = FN / N_drone；误告警率 = FP / N_bird。
- 同一轨迹只计一次（冷却 3000 ms 不重复计数）。

**框质量指标**

- IoU(GT, pred)、中心距 / 目标等效边长、宽高相对误差；
- 「偏移超阈值」= IoU < 0.5，或中心距 > max(4 px, 0.15×等效边长)，或宽高误差 >25%。

**时延指标**

- pre / det / crop+cls / post / E2E，报 p50、p95、fps、峰值内存；
- E2E 定义沿用板端现有口径：`wall − playStart − ts`。

### 1.3 判定线（分层，避免用一句「95%」掩盖场景差异）

| 层级 | 集合 | 分类 | 告警 | 框 |
|---|---|---|---|---|
| **主验收 A** | 正常光照、目标等效边长 ≥16 px、单/双目标 | 每类 recall ≥95%，总体 ≥95%，macro-F1 ≥0.95；95% CI 下限 ≥0.95 | 告警准确率 **100%**；漏告警 **0**；误告警 **0** | IoU≥0.5 占比 **100%**；中心距与尺寸误差 0 超限 |
| **压力验收 B** | 逆光/弱光/远距/重叠/快速移动 | 每类 recall ≥90%，总体 ≥90%；安全关键错误（drone→bird）**=0** | 告警准确率 **100%**；漏告警 **0**；误告警 **0** | IoU≥0.4 占比 ≥98%，均值 IoU ≥0.50；单帧中心距 ≤2×等效边长 |
| **边界声明 C** | 8–16 px 目标 | 只报检出率与分类率，不纳入 95% 判定 | 不告警，标 `small/unknown` | 不计入框判定 |

样本量要求（否则 95% 没有统计意义）：

- A 集：每类 ≥500 个轨迹级实例、≥30 段独立序列；
- B 集：每个场景每类 ≥50 个实例，总计每类 ≥300；
- 告警：A 集 drone 轨迹 ≥200、bird 轨迹 ≥200，0 错误；报告「0/200 → 95% 置信上界 1.5%」这类精确表述。

> 「100%」在本文中一律定义为「给定验收集上 0 错误」，并同时给出置信上界；不写成「绝对不可能误报」。

### 1.4 与既有判定线的关系

- 鸟机判别**不改动** lt16 / AP75 / 整体 mAP 三条线，也不把鸟类数据混入原有 test 614 帧的分桶统计。
- 原 `test` 614 帧只用于「无人机侧不回退」的护栏：加入判别器后，UAV 轨迹的 drone 召回不得低于 95%，且检测 AP 不变（判别器不参与检测框回归）。
- 合成帧 19.2% 的披露规则继续适用；鸟机验收集必须**纯真实帧**。

### 3.2 弱对齐与模态缺失处理

AVID 有配对 IR，但论文明确：**对应帧不等于像素配准**。300 对抽样中 32.3% 全局位移 >5 px；264 对有标注的配对中 16.3% 的位移超过一个中位目标边长，`bB1=0.265`。AVID 每帧只有**一套 YOLO 标签（RGB 坐标，`0=bird`、`1=drone`）**，没有独立 IR 框。因此不能把 RGB 框原样套到 IR 上裁 6 通道。

处理规则：

- **主方案（训练/部署一致）**：以 RGB 框为准，IR crop 外扩 `1 + 2ρ`（默认取 2.0×，覆盖 ρ≤0.5 的多数情况）；训练时对 IR 通路做 ±6 px 随机平移，模拟残余视差；判别器用全局池化，降低位置敏感性。
- **离线对照**：按论文方法做 NMI 全局配准（±12 px）后再裁，量化「配准 vs 不配准」的差异；部署不做逐帧配准，避免额外延迟与失败模式。
- **IR-only 评估**：必须声明「IR 使用 RGB 坐标框、存在目标相对位移」，不能与 RGB 结果直接等同。

模态缺失增广仍然保留，用于 DVB 等 RGB-only 来源：

- p=0.5：保留真实 IR（AVID + 自采配对样本）；
- p=0.3：IR 三通道 = RGB 灰度复制（模拟「无热信息」）；
- p=0.2：IR 三通道置 0（模拟「IR 未接入」）。

推理时按实际输入选择：

- 有配对 IR：正常 6 通道；
- 只有 RGB：IR 用灰度复制（与训练 p=0.3 一致），并在日志写 `ir_src=rgb_fallback`；
- 不允许把「RGB 灰度复制」说成「红外证据」。

> 与初版方案的区别：鸟类**有** IR 证据（AVID），但热斑与 RGB 框存在目标级偏移；因此「热斑证据」可用，但必须先处理弱对齐，不能假设 6 通道天然逐像素对应。

### 3.3 划分与规模

- 按**序列/视频**划分，禁止同序列跨集；同一拍摄地点、同一天、同一只鸟不得跨集。
- **AVID 专项**：官方只有 Train（102 视频）/ Validation（13 视频），**没有可用的配对 Test**；以 Validation 作外部测试集，Train 内再按视频 80/20 划 train/val。禁止按帧随机划分。
- 目标规模：
  - bird：AVID 15 471 框 + DVB/自采补充，≥60 段序列、≥30 000 个标注实例；
  - drone：AVID 20 481 框 + Mendeley 全部 + 自采 ≥30 段、≥30 000 实例；
  - background/困难负样本：≥5 000 帧；
  - 鸟机同框（关键）：≥20 段、≥300 个双类共存实例；**AVID 无法提供**（115 段视频全为单一类别，0 帧同框），必须自采或从混合场景视频裁取。
- 测试集：
  - A 集：正常光照、**原生 ≥16 px**、≥500/类轨迹实例；由 Mendeley + 自采承担，**不用 AVID 上采样帧冒充**；
  - B 集：五类场景各 ≥10 段、每类 ≥50 实例；AVID 原生 8–16 px 归入本层的小目标子集；
  - C 集：原生 8–16 px 边界集，只报趋势（AVID 的 68.1% 属于此层）。
- 训练/val/test 比例按序列 70/15/15；Mendeley 原有 test 614 帧保持不变，另作 UAV 护栏。
- **AVID-C 仅作补充**：7 类扰动 ×5 严重度（噪声、模糊、光照、运动模糊、相机抖动等）可用于 B 层稳定性曲线，但必须在论文标注「模拟扰动」，不能替代逆光/弱光的真实场景测试。

### 3.4 场景定义（可测量，避免主观描述）

| 场景 | 量化条件 | 采集要求 |
|---|---|---|
| 逆光 | 背景高亮像素（Y>200）占比 ≥30%，目标局部对比度 <10% | 日出/日落逆光，目标从亮背景前穿过 |
| 弱光 | 全图平均亮度 <40（8 bit），或 SNR <10 dB | 黄昏/夜间，开启 IR |
| 远距离 | 目标等效边长 12–24 px（C 集边界另计） | 50–300 m，变焦固定 |
| 多目标重叠 | 同帧 ≥3 目标，任两框 IoU 0.1–0.5 或遮挡 ≥30% | 鸟群/双机/鸟机同框 |
| 快速移动 | 帧间位移 >2×目标边长，或运动模糊长度 ≥5 px | 近距离横穿、快速俯冲 |

每个场景至少 10 段、每段 10–30 s、25 fps；固定曝光/增益档位并记录，避免用自动曝光掩盖问题。

   ```
   SOURCES.md
   ```
2. 标签转换脚本统一输出 YOLO 格式 `cls cx cy w h`，`cls∈{0,1}`；`ignore` 用单独清单，不写进训练标签。
3. 序列级划分，生成 `split.json`，并做泄漏检查（同 seq_id / 同 site+date 不得跨集）。
4. 生成统计报告：每类实例数、每场景实例数、边长分布、IR 可用率、鸟机同框段数。
5. 10% 双人复核，类别一致率 <98% 则返工。

**G0 不通过就不训练**，避免用不可用数据刷出一个无法写进论文的数字。

### 5.3 D0 诊断（零训练，半天内可完成）

目的：判断现有 UAV 检测器能否作为鸟类提议器。

- 用 `mdp150_M0_concat_s0` 的 640 与 736 两个推理档，在鸟测试集上跑 `pf_export.py` + 自定义匹配脚本；
- 统计：
  - 鸟目标被任一类框命中（IoU≥0.3）的比例 `bird_proposal_recall`；
  - 鸟框被误判为 UAV 的分数分布；
  - 每帧候选框数量、重复框比例（NMS-free 的 top-k 行为）；
  - 鸟群/重叠场景的漏检率。
- 判定：
  - `bird_proposal_recall ≥90%` 且重复框可控 → **R1**；
  - 否则 → **R2**；
  - 若 90% 附近且重叠场景差 → R1 + 鸟检测器兜底（R3）。

产出 `reports/d0_bird_recall.json`，并在台账 E27 记录。**不训练、不改模型。**

### 5.4 T1 二类检测器（主路线）

- 配置：复制 `yolo26n-mm-dual-fusion-concat.yaml` 为 `...-nc2.yaml`，`nc: 2`，`names: {0: bird, 1: drone}`（与 AVID 标签一致）。
- 初始化：加载 `mdp150_M0_concat_s0/weights/best.pt`，替换检测头；前 10 epoch 冻结 backbone/neck，只训 head；之后全解冻。
- 数据：Mendeley UAV 帧 + 鸟类帧按 1:1 采样；每 epoch 保留 5–10% 纯背景；鸟样本按序列均衡，避免长序列主导。
- 超参：150 ep / patience 30 / 640 / mosaic 1.0 / close_mosaic 15 / `amp false`；batch 优先 32，显存不足改 16 并在论文标注协议偏差；seed 0 与 seed 1 两次。
- 增强：HSV、尺度、mosaic；运动模糊（快速移动）、亮度/伽马（逆光/弱光）；**不做单侧几何增强**（对齐守卫）。
- 选模型：val 上按 `bird AP50 + drone AP50` 的调和均值选，不用 test。
- 门禁：
  - UAV：lt16 AP50-95 相对 M0 回退 ≤1 pp，整体 ≥0.7449；
  - bird：AP50 ≥0.70、AP75 ≥0.45（首版目标，先保证能检出）；
  - 无 GT 帧误检 ≤2/66。
- 失败处置：若 UAV 回退 >1 pp，回退 R1 级联（不改 UAV 检测器）；R1 仍不达标再考虑 R3 双提议器。

### 5.5 T2 鸟/机判别器（条件触发：E28 未达线才启动）

**样本构造**

- 正样本：GT 框扩展 1.5×，保持长宽比，resize 到 96×96；
- 训练分布对齐推理：50% 用 GT 框，50% 用检测器输出框（IoU 0.5–0.9，jitter ±10%），避免「训练见完美框、推理见抖动框」；
- 难负样本：背景 crop、云、树枝、风筝、飞机、昆虫、鸟群中的遮挡个体；
- 每类 ≥20 000 crop；按序列划分 train/val/test；鸟机同框样本单独留出评估。

**模型**

- MobileNetV3-Small 改造：输入 6 通道（第一层 conv 改 6），输出 2 类；约 0.6 M 参数，int8 约 1.5 MB；
- 备选：4-block 自建 CNN（更稳的 RKNN 兼容性）；两者在 val 上二选一，不并行烧卡。

**训练**

- 60 ep，AdamW lr 1e-3，cosine，warmup 3，batch 128，label smoothing 0.05；
- 类别权重按实例数反比；鸟/机 1:1 采样；
- 早停看 val macro-F1；保存 best 与 last；
- 温度标定在 val 上做，test 不动；
- 三个 seed（0/1/2），报均值±σ；判别器训练便宜，三次重复是必须的。

**门禁**

- val macro-F1 ≥0.97（给 test 的 0.95 留 2 pp 余量）；
- 鸟→机（误警方向）≤1%，机→鸟（漏警方向）≤1%；
- 分场景 val：逆光/弱光/远距各 ≥0.93，否则回到 T0 补数据。

### 5.6 T3 时序融合与告警状态机（无训练，只标定）

**轨迹级投票**

- 每条轨迹保留最近 5 次高置信观测的类别概率；
- 类别分数 = 均值；`drone_score`、`bird_score`；
- 迟滞：新类别需连续 4/5 帧胜出才切换，抑制抖动。

**告警规则（部署态）**

```
if track.confirmed
   and track.age >= 5
   and cls == drone
   and drone_score >= 0.70
   and box_equiv_side >= 12 px
   and cooldown(3000 ms) passed:
       alert()
elif cls == bird:
       draw("bird"); no alert
else:
       draw("unknown"); no alert
```

- 对 8–16 px 目标：只画框与 `small`，不告警；
- 对 `drone_score` 在 0.5–0.7 的轨迹：延长到 T=8 再判；仍不确定则按 `bird` 处理（不告警）并记 `low_conf`，**但要单独统计这部分**，不能藏进 95%。

**阈值标定**

- 只在 val 上网格搜索：`drone_score` 阈值 0.5–0.9、确认帧数 3–8、冷却 1–5 s；
- 目标函数：先满足「漏警=0」，再最小化误警，再最大化 F1；
- 锁定后写 `deploy_thresholds.json`，test 只跑一次，禁止回调试凑。

### 5.7 T4 量化与格式转换

- 检测器（R1 沿用 / R2 新训）：
  - `export_onnx_raw.py` → ONNX（6 通道，NHWC 或 NCHW 按现有链路）；
  - `build_calib.py` 构建 300–500 张校准集：drone/bird 各半，覆盖五个场景，必须与推理分辨率一致；
  - `convert_rknn.py --target rk3588 --precision int8 --algo normal --std unit`；
  - `sim_check.py` 比对 cos、top1；要求 cos ≥0.99、分类掉点 ≤1 pp。
- 判别器：
  - 96×96×6 输入，int8；校准集从同类 crop 抽 300 张（两类均衡、含逆光/弱光）；
  - 输出 2 类 logits；同样做模拟器比对。
- 版本匹配：toolkit 2.3.2 → 板端 librknnrt 2.3.0；升级任一端前先查主版本约束。
- 产物命名：`model_bd_det_640.rknn`、`model_bd_cls_96.rknn`，附 `*.sim.json`、`calib.txt`、转换日志。

## 6. 端侧部署与实时流水线

### 6.1 现有基础（可直接复用）

- `rk_capture_v4l2.c`：V4L2 双路采集，NV12；
- `rk_pre.c`：NV12→BGR/灰度→letterbox→6 通道，8 线程，int8 直喂；
- `rk_model.c`：RKNN 封装 + 三头并行解码，`C = 4 + nc`，NMS-free；
- `rk_track.c`：ByteTrack-lite + 卡尔曼 + N 帧确认 + 冷却；
- `rk_alert.c` / `rk_ui.c`：JSONL 告警、UI 叠加；
- `rk_ui_main.c` / `rk_stream.c`：采集→预处理→推理→跟踪→告警主循环。

### 6.2 必须修改的点

| 文件 | 改动 | 原因 |
|---|---|---|
| `rk_model.c` | 解码时保留 `argmax cls`；`C=4+nc` 已支持，补类别索引与分数 | 现在只取 max score，类别丢失 |
| `rk_model.c` | 新增 `mdl_infer_cls()` 或第二模型加载接口 | 级联判别器 |
| `rk_track.c` | 关联增加类别一致性惩罚；轨迹内维护 5 帧类别票 | 防止 ID 切换导致类别跳变 |
| `rk_alert.c` | 仅 `cls==0` 触发；JSON 增加 `cls_name`、`drone_score`、`bird_score` | 现在对所有确认轨迹告警 |
| `rk_ui.c` / `rk_ui_main.c` | drone 红框、bird 蓝框；标注文案严格为小写 `drone` / `bird`；bird 不闪红 | 验收要求逐字一致 |
| `rk_ui_main.c` / `rk_stream.c` | `NET` 从宏改为运行时参数；新增判别器阶段；crop 从 6 通道张量直接取 | 640/736 切换与级联 |
| `rk_pre.c` | 新增 `pre_crop6()`：从已 letterbox 的 int8 张量裁 ROI 并 resize 到 96 | 避免二次解码/二次预处理 |
| `rk_capture_v4l2.c` | 双路时间戳配对、丢旧帧策略、断流重连 | 实时视频流稳定性 |

### 6.3 数据流转与线程模型

```
[RGB V4L2 采集线程] --ring(cap=4, drop-oldest)─┐
[IR  V4L2 采集线程] --ring(cap=4, drop-oldest)─┤
                                               ├→ [预处理线程] → 6ch int8 双缓冲
                                               │       ↓
                                        [主线程: det → 解码 → 反变换]
                                               ↓
                                   [仅 confirmed 轨迹: crop6 → cls]
                                               ↓
                                   [跟踪/投票 → 告警门控 → UI]
```

优化要点：

1. **零拷贝**：`pass_through=1`，预处理直接写模型原生 int8，避免每帧 2.4 M 元素归一化（历史上该项占 88 ms）。
2. **crop 从张量取**：判别器 ROI 直接从 640 的 6 通道 int8 张量裁切，不再回原始 NV12 重采样。
3. **判别器只跑确认轨迹**：未确认轨迹不分类，减少 60–80% 的 crop 次数。
4. **多目标批处理**：同一帧的 crop 拼 batch 一次推理，避免 N 次 `rknn_run`。
5. **隔帧分类**：目标数 >8 时判别器隔帧跑，类别沿轨迹保持；UI 不闪。
6. **丢旧帧**：采集 ring 满时丢最旧帧，保证延迟不累积；日志记录 `ring_drop`。
7. **上屏与推理解耦**：UI 只读最近结果，不阻塞主循环。
8. **固定内存**：所有缓冲启动时分配，主循环零 malloc。

### 6.4 时延预算（640 实时档）

| 环节 | 预算 | 依据 |
|---|---|---|
| 采集+ring | 0（异步） | 采集线程独立 |
| 预处理 | 22.4 ms | 640 实测 22.36 |
| 检测 NPU | 71.9 ms | 640 实测 run 71.92 |
| 解码+反变换 | 1.1 ms | 实测 dec 1.08 |
| crop+判别器 | 6–10 ms | 预估（≤8 目标，batch） |
| 跟踪+告警+上屏 | 4–6 ms | 预估 |
| **E2E** | **105–112 ms** | 目标 ≤120 ms |

736 档：24.4 + 89.4 + 1.3 + 8 + 5 ≈ 128 ms → 超线，只作精度档。

### 6.5 真机接入

- 双 V4L2 摄像头：`/dev/video0`（RGB）、`/dev/video1`（IR），分辨率与帧率固定，关闭自动曝光/自动增益并记录档位；
- 单摄像头时：RGB 正常，IR 用灰度复制，日志标 `ir_src=rgb_fallback`；论文必须写明该场景不构成双光谱证据；
- 时间同步：以 RGB 帧时间戳为基准，取「不早于 RGB 的第一帧 IR」，记录配对残差；
- 断流/掉线：3 s 超时重连，UI 显示 `DEGRADED`，不静默失败。

## 7. 验证方案

### 7.1 离线验证（服务器）

1. 检测器/判别器在 A/B/C 集上导出逐帧结果；
2. `eval_birddrone.py` 统一计算：混淆矩阵、per-class recall、macro-F1、告警 TP/FP/FN、框 IoU/中心距/尺寸误差；
3. 轨迹级投票复现部署逻辑（T=5、迟滞 4/5、阈值同 `deploy_thresholds.json`）；
4. 序列聚类 bootstrap 给 CI；
5. 输出 `reports/birddrone_A.json`、`_B.json`、`_C.json` 与一页汇总表。

### 7.2 端侧验证（RK3588）

- 板端跑 `eval_birddrone` 的 C 版本或 `rk_stream` + JSONL 后处理；
- 输入：真实相机 30 min + A/B 集视频回放；
- 记录：`seq / ts / pre / det / cls / post / e2e / nDets / tracks / gt / alerts / cls_name / score / ir_src`；
- 判定：
  - E2E p95 ≤120 ms（640 档）；
  - 30 min 无崩溃、无内存增长（VmHWM 波动 <5%）；
  - 板端与服务器 ORT 的分类一致率 ≥98%（同帧同框）；
  - 告警事件与离线复算一致（允许因丢帧产生的边界差异，需逐条解释）。

### 7.3 复杂场景测试矩阵

| 场景 | 段数 | 每类实例 | 重点检查 | 失败判据 |
|---|---|---|---|---|
| 逆光 | ≥10 | ≥50 | 鸟剪影是否误判为机；框是否被光晕拉大 | 安全关键错误 >0 |
| 弱光 | ≥10 | ≥50 | IR 是否真的提供信息；RGB 噪声下分类 | 鸟→机 >1% |
| 远距离 | ≥10 | ≥50 | 12–24 px 分类率；是否该降级为 small | 机→鸟 >0（漏警） |
| 多目标重叠 | ≥10 | ≥50 | 框合并/ID 切换/类别串扰 | 漏警 >0 |
| 快速移动 | ≥10 | ≥50 | 运动模糊、跟踪预测、时间戳配对 | 框偏移超限 >2% |

每个场景固定同一批权重、同一阈值、同一曝光档；不允许按场景调阈值后再报 100%。

### 7.4 消融（论文用）

| 编号 | 对照 | 目的 |
|---|---|---|
| Ab1 | RGB-only 判别器 vs 6 通道 | 证明 IR 是否真的有用（很可能没用，需如实写） |
| Ab2 | GT 框 crop vs 检测框 crop | 量化「提议器误差」对分类的影响 |
| Ab3 | 单帧 vs T=5 投票 | 时序证据的边际收益 |
| Ab4 | 级联 vs 二类单阶段（R2） | 路线选择依据 |
| Ab5 | 上下文扩展 1.2× / 1.5× / 2.0× | 远距离与重叠的折中 |

## 8. 判定线与失败处置

| 门禁 | 通过条件 | 不通过怎么办 |
|---|---|---|
| G0 数据 | 许可齐备；bird ≥60 序列/30k 实例；双人复核 ≥98% | 停止训练，先补数据；不得用 Anti-UAV 冒充鸟 |
| D0 | 鸟提议召回 ≥90% | 转 R2 二类检测器 |
| G1 检测器（R2） | UAV 回退 ≤1 pp；bird AP50 ≥0.70 | 回退 R1；或 R3 双提议器 |
| G2 判别器 val | macro-F1 ≥0.97；双向错误 ≤1% | 补困难负样本/提高 crop 到 128/加 IR 缺失增广 |
| G3 量化 | cos ≥0.99；分类掉点 ≤1 pp | 调校准集、改 per-channel、必要时敏感层 fp16 |
| G4 运行时 | E2E p95 ≤120 ms；30 min 稳定 | 降 640、隔帧分类、减少 crop 数 |
| G5 主验收 A | 每类 ≥95%、告警 0 错、框 100% 达标 | 只报实际边界；禁止调阈值凑数 |
| G6 压力 B | 每类 ≥90%、安全关键错误 0、告警 0 错 | 标注场景边界；远距降级为 small |

**止损原则**

- 若 G2 在 96×96 下卡在 0.93–0.95，不无限加训练轮次；优先补数据与提高 crop 分辨率，并把「12–16 px 不可判别」写成明确边界。
- 若 6 通道不优于 RGB-only，如实写「IR 在鸟类判别上无增益」，这本身是双光谱系统的有效边界结论。
- 若 R2 回退 UAV，坚决回 R1；不得为了「单阶段更优雅」牺牲已验证指标。
